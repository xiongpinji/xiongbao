X-Agent 支持与故障升级路径 v1

用途：为当前候选提供最小可执行的支持边界、故障升级路径和角色分工入口。

适用范围：内部试点、受控私有部署、单机 / Compose full 模式交付。

注意：当前文档先固化“角色与流程”，不伪造真实联系人信息。真实姓名、值班 IM、电话、邮箱和升级 SLA 必须在具体环境交付时补齐。

1. 当前支持模型

当前建议采用四层支持模型：

  1. L1 现场支持 / 值守
  2. 负责健康检查、日志收集、基础重启、信息归档；

  3. 不能私自改候选范围、不能跳过回滚流程。

  4. L2 发布负责人 / 平台负责人

  5. 负责候选绑定、配置核对、发布执行、回滚决策；

  6. 处理 secret / 依赖服务 / 环境差异问题。

  7. L3 研发负责人 / 仓库维护者

  8. 负责代码级问题、契约问题、E2E/运行时异常分析；

  9. 决定是否需要生成补丁候选。

  10. L4 Owner / 最终签字人

  11. 负责试点边界确认、风险接受、正式交付签字或延期决策。

2. 故障分级建议

P0

  • 系统不可用；
  • 登录、运行、Run Console 主链完全阻断；
  • 数据损坏或重大安全事件。

要求：

  • 立即升级到 L2 + L3；
  • 若在发布窗口内无法快速恢复，应准备回滚；
  • Owner 需要知情。

P1

  • 核心能力明显异常，但存在替代路径；
  • worker / workflow 大面积失败；
  • LLM 路径不稳定，影响试点流程。

要求：

  • L1 收集证据；
  • L2 组织排障；
  • 必要时升级 L3。

P2

  • 局部页面异常；
  • 文案、展示、非关键链路问题；
  • 不影响本次发布主目标。

要求：

  • 进入缺陷池；
  • 不应直接阻断发布，除非与试点承诺范围冲突。

3. 故障升级路径

3.1 第一响应

L1 现场支持在收到故障后，先做：

  1. 记录时间、环境、候选版本、触发步骤；
  2. 记录 /health、/ready、前端入口结果；
  3. 导出 docker compose ps；
  4. 导出 api / worker / web 日志；
  5. 判断是否属于：
  6. 配置缺失
  7. 依赖未启动
  8. 登录问题
  9. LLM 路径问题
  10. 代码级异常

3.2 升级到 L2

满足以下任一条件，升级到 L2：

  • 无法通过基础重启恢复；
  • 缺 secret / 账号 / provider 路径；
  • 发布步骤、迁移、回滚需要执行；
  • 当前环境与文档基线不一致。

3.3 升级到 L3

满足以下任一条件，升级到 L3：

  • 运行时契约异常；
  • E2E 主链失败且非环境配置问题；
  • API / worker 存在代码级栈追踪；
  • 回滚后仍不能恢复核心链路。

3.4 升级到 L4 / Owner

满足以下任一条件，升级到 Owner：

  • 需要延期发布；
  • 需要宣布本次只能按试点交付；
  • 风险需要业务接受；
  • 需要决定继续推进还是中止交付。

4. 每次升级必须附带的证据

无论升级给谁，都应附带：

  • 环境名
  • branch / commit / PR
  • CI run URL
  • /health 结果
  • /ready 结果
  • docker compose ps
  • api / worker / web 日志摘录
  • 触发步骤
  • 是否已尝试回滚
  • 当前影响范围

没有这些信息时，升级会显著降低处理效率。

5. 发布窗口内的升级规则

发布窗口内必须遵守：

  1. 不允许现场直接热修仓库代码；
  2. 不允许在未记录证据的情况下反复重启并覆盖现场；
  3. 不允许把 lite/dev 本地结果冒充 full-mode 现场结果；
  4. 超过变更窗口或核心链路不可恢复时，应按 RELEASE_RUNBOOK_V1.md 执行回滚。

6. 当前联系人占位模板

6.0 当前单人交付模式（2026-07-08）

当前仓库的真实支持模型不是多团队轮值，而是：

  • 当前唯一人类负责人：canqu（当前 owner / 发布人）
  • 当前实现与验证执行：本 Claude 会话在 owner 授权下完成
  • 因此在本轮交付中，L1 / L2 / L3 / L4 可以临时收敛为同一 owner

这意味着：

  • 对当前机器、当前候选、当前 PR 的故障升级，不需要再假设外部团队接力；
  • 若后续转入客户现场、外部运维或多角色值守，再补实名联系方式与 SLA。

6.1 当前联系人模板

交付到具体环境时，应至少补齐下面信息：

角色 姓名/团队 IM/邮箱/电话 值守时间 备注
L1 现场支持 canqu（当前 owner） 当前会话 / 当前仓库 当前交付窗口 一线收集证据
L2 发布负责人 canqu（当前 owner） 当前会话 / 当前仓库 当前交付窗口 发布、回滚、配置
L3 研发负责人 canqu（当前 owner） 当前会话 / 当前仓库 当前交付窗口 代码与契约异常
L4 Owner canqu（当前 owner） 当前会话 / 当前仓库 当前交付窗口 风险接受与最终决策

当前没有额外的外部联系方式字段时，不应伪造手机号或邮箱；对本轮单人交付，这不再构成单独阻断。若进入外部团队或客户现场，再补真实企业联系方式。

7. 当前结论

这份升级路径文档现在可以解决：

  • 发布 / 试点时出了问题，应该先找谁；
  • 哪类问题应升到哪一层；
  • 升级时要附什么证据。

但它还不能单独证明：

  • 联系人网络已经完全到位；
  • 支持 SLA 已签字确认；
  • 正式交付值守体系已经完成。
