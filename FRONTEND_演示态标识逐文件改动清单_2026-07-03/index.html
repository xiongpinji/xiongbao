前端“演示态标识”逐文件改动清单（2026-07-03）

目标：把“演示态标识方案”进一步落成可执行的逐文件改动说明。 范围：仅覆盖当前最容易让用户误解为“真实智能执行”的页面与组件。 不包含代码实现，只说明“改哪里、加什么、优先级如何”。

1. 改动优先级

P0（本轮建议必须补）

  1. src/pages/AgentsPage.tsx
  2. src/pages/MemoryPage.tsx
  3. src/pages/OpenSourcePage.tsx
  4. src/components/settings/SettingsLayout.tsx
  5. src/components/layout/ShellContextPanel.tsx

P1（建议补）

  1. src/components/runs/RunConsole.tsx
  2. src/pages/WorkflowsPage.tsx
  3. src/pages/CreativeStudioPage.tsx

P2（当前不建议动）

  • src/pages/LoginPage.tsx
  • src/pages/ChatPage.tsx
  • src/pages/ProfessionalModePage.tsx
  • src/components/layout/AppShell.tsx

原因：这些页面当前更接近真实主入口或壳层，不适合统一打上“预览态”标签。

2. 逐文件改动清单

2.1 src/pages/AgentsPage.tsx

当前问题

页面视觉上像“可真实调度多个专业智能体”，但实际上：

  • 后端失败时会显示 fallbackRoles
  • 对话助手当前主要返回本地建议文案
  • “设为当前角色”按钮也更偏演示态

建议改动位置 A

位置： 角色标题区下方，selected.description 下方附近。

当前代码参考区域： - Agent profile - 角色名 - selected.description

建议新增文案

当前页用于浏览和预览智能体角色。角色说明与调度建议可用于工作流设计，但真实执行能力仍以后端返回的可用角色与工具链为准。

建议改动位置 B

位置： ConversationalCommand 上方，作为一条轻提示。

建议新增文案

预览态：当前“角色调度”优先生成任务拆解建议，不直接触发真实智能体执行。

建议改动位置 C

位置： 保留现有 error 提示框，但把文案再说透一点。

当前文案：

后端角色接口暂不可用，当前展示本地预览角色用于 UI 演示。

建议替换为：

后端角色接口暂不可用，当前展示的是本地演示角色，仅用于 UI 预览，不代表真实可调度角色集合。

优先级

  • 必须改：A、C
  • 建议改：B

2.2 src/pages/MemoryPage.tsx

当前问题

“记忆检索助手”看起来像可以直接从知识库返回结果，但当前行为更偏：

  • 整理检索意图
  • 给出记忆隔离建议
  • 跳转到设置页

建议改动位置 A

位置： header 段落下方、ConversationalCommand 上方。

建议新增文案

辅助模式：当前入口主要用于整理检索意图与跳转索引配置，不直接展示真实知识库命中结果。

建议改动位置 B

位置： ConversationalCommand 的 initialAssistantMessage。

当前文案：

你可以直接问知识库，也可以要求我把当前信息沉淀到某个项目或智能体的专属记忆区。

建议替换为：

你可以先描述检索或沉淀目标。我会优先整理检索意图、隔离边界和下一步入口；真实知识库结果仍需进入索引库或后端检索链路查看。

优先级

  • 必须改：A
  • 建议改：B

2.3 src/pages/OpenSourcePage.tsx

当前问题

“开源比选助手”很容易让用户误会成实时仓库搜索，但当前更接近：

  • 能力缺口整理
  • 比选维度建议
  • 配置页导航

建议改动位置 A

位置： header 段落下方、ConversationalCommand 上方。

建议新增文案

预览态：当前入口优先整理开源比选目标与接入策略，不直接返回实时仓库搜索结果。

建议改动位置 B

位置： ConversationalCommand 的 initialAssistantMessage。

当前文案：

告诉我你要补齐的能力，我会先按功能、许可证、成熟度和接入方式拆分比选。

建议替换为：

告诉我你要补齐的能力，我会先整理比选目标、许可证关注点和接入策略。真实候选仓库列表仍需进入开源发现链路进一步检索。

优先级

  • 必须改：A
  • 建议改：B

2.4 src/components/settings/SettingsLayout.tsx

当前问题

“配置助手”容易让用户误解为：

  • 输入一句话后，配置已经真的被修改

但当前更偏：

  • 生成检查清单
  • 输出建议
  • 转成交付任务

建议改动位置 A

位置： ConversationalCommand 上方。

建议新增文案

辅助模式：配置助手当前只生成检查清单与调整建议，不会直接修改本地或远端配置。

建议改动位置 B

位置： initialAssistantMessage

当前文案：

你可以直接告诉我想怎么配置「xxx」，我会把自然语言转成可执行的配置检查清单。

建议替换为：

你可以直接告诉我想怎么配置「xxx」。我会把自然语言整理成检查清单与调整建议，但不会直接写入配置。

优先级

  • 必须改：A
  • 建议改：B

2.5 src/components/layout/ShellContextPanel.tsx

当前问题

右侧“上下文助手”很像“当前页真实智能代理”，但当前更偏：

  • 总结当前页
  • 给下一步建议
  • 帮助转成工作流任务

建议改动位置 A

位置： ConversationalCommand 上方。

建议新增文案

辅助模式：当前为上下文助手，优先提供总结、建议与跳转，不直接执行后台任务。

建议改动位置 B

位置： initialAssistantMessage

当前文案：

我会根据当前页面上下文回答，并把你的意图转成下一步操作。

建议替换为：

我会根据当前页面上下文给出总结、建议与下一步入口，必要时再引导你进入真实执行页面。

优先级

  • 必须改：A
  • 建议改：B

2.6 src/components/runs/RunConsole.tsx

当前问题

“运行分析助手”当前主要根据现有 RunDetail 本地组织回答，容易被理解成“已经触发后台深度诊断”。

建议改动位置 A

位置： ConversationalCommand 上方。

建议新增文案

说明：当前分析助手优先基于已加载的运行详情做本地总结，帮助你快速查看 Timeline、Evidence 和 Artifacts。

建议改动位置 B

位置： initialAssistantMessage

当前文案：

我会把运行详情当成一条可追问的会话，按时间线、证据和产物回答。

建议替换为：

我会基于当前已加载的运行详情回答，并按时间线、证据和产物帮你快速定位信息。

优先级

  • 建议改：A
  • 可选改：B

2.7 src/pages/WorkflowsPage.tsx

当前问题

“工作流编排助手”当前会把输入直接写成页面步骤草案，但用户可能误会为已经进入正式后端工作流编排。

建议改动位置 A

位置： ConversationalCommand 上方。

建议新增文案

预览态：这里会先生成页面内步骤草案；正式执行仍以“创建并执行”按钮触发的后端工作流为准。

建议改动位置 B

位置： initialAssistantMessage

当前文案：

你说一句目标，我会把它写入工作流步骤，并同步到画布节点。

建议替换为：

你说一句目标，我会先把它写成页面内步骤草案并同步到画布；确认后再通过执行按钮提交后端工作流。

优先级

  • 建议改：A
  • 可选改：B

2.8 src/pages/CreativeStudioPage.tsx

当前问题

Creative / Drama 页里既有草案、画布、节点编辑，又有真实执行动作。若缺少提示，用户容易混淆“草案生成”和“正式生产”。

建议改动位置 A

位置： 对话式入口附近（如果存在独立 ConversationalCommand，就放其上方；如果没有，放在 brief / 画布入口上方）。

建议新增文案

说明：当前输入会优先生成创作草案与页面节点意图；正式生产链路仍以明确的执行按钮和后端返回结果为准。

建议改动位置 B

位置： 若页面已有“创建画布 / 生成 / 运行”区块，可在按钮区附近增加一句短提示。

建议文案：

“创建画布”用于生成草案；“执行 / 生产”才会进入真实后端链路。

优先级

  • 建议改：A
  • 可选改：B

3. 建议的统一样式

为了避免每个页面都做成大黄条或大红条，建议统一采用“轻提示卡片”或“小字说明”。

方案 A：小字说明（推荐）

适合放在 ConversationalCommand 上方：

辅助模式：当前入口只整理意图与建议，不直接触发真实执行。

方案 B：细边框轻提示卡片

适合 Agents fallback 和 Settings：

当前展示的是本地演示数据，仅用于 UI 预览。

方案 C：标题旁小标签

适合 Run Console / ShellContextPanel：

  • 辅助模式
  • 预览态
  • 本地分析

4. 最小改动落地顺序

如果本轮只想最小成本降低误导风险，建议按下面顺序落：

  1. AgentsPage.tsx
  2. MemoryPage.tsx
  3. OpenSourcePage.tsx
  4. SettingsLayout.tsx
  5. ShellContextPanel.tsx

这 5 个改完，误导风险会明显下降。

如果还有余力，再补：

  1. RunConsole.tsx
  2. WorkflowsPage.tsx
  3. CreativeStudioPage.tsx

5. 与提交方案的对应关系

建议这些“演示态标识”改动归入你前面拆的 第二次提交：

feat(web): add conversational entry points across workspace pages

原因：

  • 它们都服务于“页面内对话式交互增强”的真实边界说明
  • 不适合混进“壳层 / 导航 / 主题重构”那次提交

6. 下一步建议

如果要继续推进，最顺的方式是：

  1. 先按本清单改 P0 的 5 个文件。
  2. 跑一遍页面点击验收。
  3. 再决定是否补 P1 的 3 个文件。

这样能避免一次性改太多文案，反而打断你当前前端收口节奏。
