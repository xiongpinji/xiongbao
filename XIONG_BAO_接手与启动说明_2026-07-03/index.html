XIONG BAO 项目接手与启动说明（2026-07-03）

适用对象：当前或下一位接手 xiong bao/xagent 的开发者。 目标：快速回答「项目现在是什么状态、怎么启动、为什么之前会感觉启动不了、接下来先做什么」。

2026-07-06 更新：本文保留 2026-07-03 接手现场记录；当前发布 / 商用 readiness 判断以 docs/COMMERCIAL_STATUS_SOURCE_OF_TRUTH.md 为准。本轮 readiness 已补 frontend lint/typecheck/build、关键 E2E、release runbook 与环境基线证据，但仍未宣称正式商用 GA。

1. 一句话现状

xagent 当前处于主链可运行 + 前端仍在活跃迭代 + 运行时一致性仍在继续硬化的研发态，不是完全静态封板的成品状态。

这句话比“全部完成”更贴近当前仓库现实：

  • lite / dev 路径当前已验证可以启动。
  • 前端工作台存在较多未提交改动，说明工作仍在推进中。
  • docs/superpowers/plans/2026-07-01-unified-runtime-phase2-a.md 仍在描述 unified runtime 的下一轮加固计划。

5. 已验证可用的启动 SOP（推荐接手路径）

推荐优先走 lite / dev 路径，先确认前后端和登录链路正常，再决定是否切 full / compose。

5.1 后端（lite / dev）

在 apps/api 目录执行：

pip install -e ".[dev]"
xagent serve

默认端口：

  • API：http://127.0.0.1:8000
  • 健康检查：http://127.0.0.1:8000/health
  • 文档：http://127.0.0.1:8000/docs

5.2 前端（dev server）

在 apps/web 目录执行：

npm install
npm run dev

默认端口：

  • Web：http://127.0.0.1:3000

5.3 登录

当前已验证可用的 lite / dev 默认账号：

  • 用户名：admin
  • 密码：admin

5.4 启动后最小验收顺序

建议每次接手都按这 4 步走：

  1. 打开 http://127.0.0.1:8000/health
  2. 打开 http://127.0.0.1:3000
  3. 在 lite / dev 下用 admin / admin 登录；full / prod 需使用显式配置的账号
  4. 登录后确认首页 / 工作台不报错，再继续排查业务问题

6. full / compose 路径注意事项

如果走 docker compose，请注意这不是和 lite/dev 等价的路径，额外要求更多。

6.1 启动前必须先构建前端静态文件

在 apps/web 目录先执行：

npm install
npm run build

然后再执行：

cd deploy/compose
cp .env.example .env
docker compose up -d --build

6.2 常见 full 路径前置项

  • 需要正确的 JWT_SECRET
  • 需要正确的 CORS 配置
  • 需要数据库 / Redis / Qdrant / LiteLLM / Langfuse 等依赖可用
  • 若依赖宿主机 Ollama，需要确认 host.docker.internal:11434 可访问

6.3 结论

如果只是接手、排查、看页面、理解现状，不要一上来就走 compose。除非明确要验证 full 模式、worker 或持久化链路，否则优先 lite/dev。

7. 为什么之前会感觉“启动不了”

根据当前文档、日志和仓库状态，高概率不是“整个项目完全起不来”，而是以下几类问题之一。

7.1 在仓库根而不是 apps/api 下运行后端命令

这是文档反复提醒的坑。

后果：容易出现 ModuleNotFoundError: xagent。

7.2 把 lite/dev 和 full/compose 路径混用

常见误区：

  • 用 full 的预期去跑 lite
  • 用 lite 的配置去跑 full
  • 只看 README 某一段，没有对照 Runbook

结果会表现为：

  • 后端校验失败
  • 外部依赖没起全
  • worker / Celery / Redis 链路异常
  • LLM provider 不通

7.3 前端代理目标指错

前端 dev server 默认通过 XAGENT_DEV_API_TARGET 代理到后端。

默认值是：

http://localhost:8000

如果之前切过 worktree、多开过端口，可能会出现：

  • 前端打开了
  • 但请求仍打到旧端口 / 旧实例
  • 页面看起来像“没启动”或“接口全挂”

7.4 未登录导致前端接口返回 401

在结构化日志里可以看到：

  • /api/v1/agents/roles 曾出现 401 Unauthorized
  • 后续又恢复为 200

这说明某些时刻服务本身已经起来，但页面在未登录或 token 丢失状态下访问鉴权接口，用户容易误判为“项目没启动成功”。

7.5 compose 路径缺少 apps/web/dist

这是另一个高频坑。

如果直接 docker compose up，但没有先跑 npm run build，web 容器可能无法正常提供前端页面。

8. 当前主要卡点与风险

8.1 文档口径偏“完成态”，仓库现实偏“迭代态”

项目总览与开发指南 中有大量“全部完成 / 已验证 / 商用就绪”的描述，但当前仓库仍有大量前端未提交改动，并且还有新的运行时加固计划。

风险：

  • 新接手者会预期这是封板成品
  • 但实际面对的是持续演进中的研发仓
  • 进而把“体验不稳定 / 页面未收口 / 鉴权未恢复”误判为“项目坏了”

8.2 当前工作区前端改动面较大

当前前端 diff 已经覆盖：

  • AppShell
  • TopBar / Sidebar / ContextPanel
  • 多个 page
  • RunConsole
  • 全局样式
  • 登录页

风险：

  • 2026-07-06 R2 已完成 npm run lint、npm run typecheck、npm run build 本地验证；若继续改前端，交付前仍需重跑。

8.3 运行日志未清理，容易干扰下一位接手者判断

当前仓库里直接存在运行日志文件，容易造成两种误解：

  • 被误当成正式项目文件
  • 被旧日志误导，以为是“当前最新问题”

8.4 默认账号仍可用，安全口径仅适合本地接手

admin / admin 当前仅适合 lite / dev 本地调试，不适合被误当作 full / prod 设置。

9. 接手后的优先任务建议（按顺序）

P1：若前端继续改动，先复跑类型检查与构建

建议执行：

cd apps/web
npm run typecheck
npm run build

目的：

  • 判断本次改动后的前端工作区是否仍处于可继续开发状态
  • 为后续继续推进 UI/交互工作提供基线

P2：如果前端通过，再补一次后端最小基线检查

建议执行：

cd apps/api
xagent info
xagent serve

必要时补：

curl http://127.0.0.1:8000/health

目的：

  • 保证当前接手环境下前后端基线都正常

P3：再决定是推进前端工作台，还是继续 phase2-a runtime 加固

判断方法：

  • 如果当前前端工作区已接近完成，优先继续做前端收口。
  • 如果 Run Console / runtime detail / failure bundle 仍是最近重点，则转向 docs/superpowers/plans/2026-07-01-unified-runtime-phase2-a.md 中的收口任务。

10. 接手者 5 分钟操作清单

只想先确认项目活着

  1. 进入 apps/api，运行 xagent serve
  2. 打开 http://127.0.0.1:8000/health
  3. 进入 apps/web，运行 npm run dev
  4. 打开 http://127.0.0.1:3000
  5. 在 lite / dev 下用 admin / admin 登录

想继续当前工作

  1. 先看本文件
  2. 再看 docs/项目总览与开发指南.md
  3. 执行 npm run typecheck
  4. 执行 npm run build
  5. 根据结果决定是修前端当前改动，还是转去 runtime phase2-a

11. 本次接手给出的工作判断

当前最靠谱的判断

  • 项目不是“完全启动不了”。
  • 项目更像是“能启动、能登录、能继续开发，但每轮前端或运行时改动后仍需要复跑基线验证”。
  • 2026-07-06 已补齐前端 lint/typecheck/build 与关键 E2E 的本地证据；后续按任务板继续补远端 CI、目标环境演练和 PR 审查包。

推荐的下一步

若继续修改前端，先执行 apps/web 下的 npm run lint、npm run typecheck 和 npm run build；若不改前端，按 docs/coordination/TASK_BOARD.md 领取下一张 READY 任务。
