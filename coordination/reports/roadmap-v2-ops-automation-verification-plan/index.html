Roadmap v2 B 自动化运营增强真实验证计划

适用阶段：Roadmap v2

用途：把 B 自动化运营增强包从“方向定义”推进到“可执行验证”，明确自动告警、自动恢复、自动证据归档和自动运行态汇总的验证范围、方法与证据要求。

1. 目标

本计划的目标是：

为 xagent 的自动化运营增强路线提供第一份真实验证计划，使 B 包不再停留在概念层，而进入可验证状态。

2. 验证范围

本次验证只覆盖以下内容：

  1. 当前哪些运营动作仍依赖人工；
  2. 当前哪些步骤已经具备可自动化的前提；
  3. 哪些证据收集动作可以优先自动化；
  4. 哪些运行态汇总入口已经存在；
  5. 当前自动化增强的第一步应该落在哪些最小场景上。

本次验证不要求一次性完成： - 全自动发布； - 全自动恢复； - 全自动审计归档； - 全量值守编排平台。

3. 验证环境

当前优先采用： - 仓库中已有运维手册、发布/回滚手册、支持升级路径、G1/G2/G3 包的等价验证环境； - 用于识别哪些操作已经是结构化步骤、可以成为自动化候选。

环境前提： - 能读取 OPERATIONS_MANUAL_V1.md - 能读取 RELEASE_RUNBOOK_V1.md - 能读取 SUPPORT_ESCALATION_PATH_V1.md - 能读取 commercialization-goal-board.md 与 G1/G2/G3 相关包文档

4. 验证项

4.1 当前仍依赖人工的动作

至少识别： - 故障出现后的人工判断 - 手工收集日志与健康检查结果 - 手工回填证据文档 - 手工判断是否回滚 - 手工整理最终运行态结论

期望： - 这些动作被明确列出来，而不是模糊说“以后自动化”。

4.2 已具备自动化前提的动作

至少识别： - /health / /ready 结果采集 - docker compose ps 与日志抽样采集 - 关键验证命令的执行结果记录 - Goal / Task / Run / Evidence 的结构化入口

期望： - 可以明确哪些动作已经足够结构化，可以优先做自动化。

4.3 自动证据归档方向

验证当前是否已经存在可自动归档的对象： - run id - task id - workflow id - CI run URL - /health / /ready 结果 - smoke / 回滚 / 演练输出

期望： - 证据归档不再完全依赖人工描述。

4.4 自动运行态汇总方向

验证当前是否已经存在可汇总的结构化入口： - Goal Board - G1/G2/G3 执行包 - delivery-report - final-summary

期望： - 自动运行态汇总至少已有明确输入面，而不是从零开始。

5. 通过标准

B 自动化运营增强包的真实验证通过，至少需要满足：

  1. 当前人工动作已被明确识别；
  2. 当前可自动化动作已被明确识别；
  3. 证据归档的自动化入口已被正式列出；
  4. 运行态汇总的自动化入口已被正式列出；
  5. 团队能够明确知道“先自动化什么”而不是继续泛泛讨论自动化。

这意味着： - B 包的“通过”不是自动化已经全部完成； - 而是自动化增强已经进入真实可执行验证阶段。

6. 证据要求

本计划要求输出的最小证据包括：

  • 当前人工动作清单
  • 可自动化动作清单
  • 证据自动归档候选入口清单
  • 运行态汇总候选入口清单
  • 最终判定：
  • 通过 / 不通过
  • 哪些已验证
  • 哪些仍是后续目标

建议归档到： - docs/coordination/reports/roadmap-v2-ops-automation-verification.md

7. 当前结论

当前 B 自动化运营增强包 已完成方向定义； 这份计划的作用是让它进入下一状态：

可执行验证

只有完成这一步，B 自动化运营增强包 才能从“方向定义”走向“验证完成”。
