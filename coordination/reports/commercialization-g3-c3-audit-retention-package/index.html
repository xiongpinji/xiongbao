G3-C3 审计 / 保留策略包

适用阶段：G3 企业级长期运营

用途：冻结 xagent 在企业级长期运营阶段需要的审计入口、数据保留方向、权限长期治理边界与多租户可追溯要求，确保系统在规模化使用时不仅能跑，还能长期受控。

1. 目标

G3-C3 的目标是：

把长期运营阶段的审计、保留、权限长期治理与多租户边界冻结成一个可执行包，为后续真正的治理落地提供明确边界。

这一步不要求现在就完成完整的企业合规体系，但必须明确：

  • 哪些数据与运行对象需要长期保留；
  • 哪些审计能力必须可回查；
  • 多租户边界在长期运营中如何理解；
  • 哪些角色对审计和保留负责任。

2. 当前已有基础

当前已经具备的基础包括：

  • task / run / workflow / evidence 已形成最小回查关系；
  • spine 相关权限资源已独立化；
  • 试点阶段的权限 / secret / 默认值边界已整理；
  • 支持升级路径和故障分级已经有最小入口。

当前可直接复用的材料：

  • docs/coordination/reports/commercialization-g1-a3-data-governance-package.md
  • docs/SUPPORT_ESCALATION_PATH_V1.md
  • docs/COMMERCIAL_RELEASE_CHECKLIST_V1.md
  • docs/COMMERCIAL_STATUS_SOURCE_OF_TRUTH.md
  • docs/coordination/reports/commercialization-goal-board.md

3. 当前缺口

3.1 审计保留缺口

当前虽然已经能回查 task / run / workflow / evidence，但仍未冻结： - 哪些运行对象必须长期保留； - 哪些日志 / 证据可以清理； - 哪些审计记录属于“长期需要保留”的范畴。

3.2 权限长期治理缺口

当前虽然已区分 viewer / member / admin，但仍未冻结： - 长期运营中权限变更如何审查； - 哪些高风险操作必须被重点审计； - 如何避免长期演进后重新落回“默认值可用 / 权限过宽”。

3.3 多租户长期边界缺口

当前仍未冻结： - 多租户数据在长期运营中的隔离要求； - 证据、run、workflow 在租户视角下的回查边界； - 哪些异常属于租户隔离事故。

4. 必须冻结的审计对象

G3-C3 至少要把以下对象列为长期治理对象：

  • Goal
  • Task
  • Run
  • Workflow
  • Evidence
  • Release
  • 关键发布 / 回滚动作
  • 关键配置 / secret / 权限变更动作

这些对象的关键要求是： - 能追到是谁发起； - 能追到结果与失败； - 能追到恢复动作； - 能在需要时支撑复盘。

5. 保留方向

当前阶段至少应把保留方向冻结为：

5.1 长期保留

  • 关键候选与发布记录
  • 关键运行失败与恢复记录
  • 审查 / 签字 / 证据包
  • 影响租户边界或权限边界的关键事件

5.2 可清理但需有策略

  • 非关键临时日志
  • 重复中间产物
  • 不再需要的本地临时证据

5.3 当前不应含糊的点

  • 不能把“保留多久”完全留空；
  • 不能把“什么都永久保留”当成治理答案；
  • 不能让租户相关证据在长期运营中失去来源与上下文。

6. 多租户与权限长期边界

G3-C3 至少要明确：

  1. 多租户数据不可混用；
  2. 权限变更应被记录；
  3. 高风险角色动作需要可回查；
  4. 试点阶段的最小权限边界在长期运营中不能倒退；
  5. 任何绕过默认安全边界的操作都必须被审计。

7. 最小通过标准

G3-C3 要通过，至少需要满足：

  1. 关键审计对象已冻结；
  2. 数据保留方向已明确；
  3. 权限长期治理边界已明确；
  4. 多租户长期边界已明确；
  5. 团队知道后续企业化治理该围绕什么补，而不是继续泛泛说“以后补合规”。

这意味着： - G3-C3 的“通过”不是完整企业合规已经实现； - 而是企业级长期治理的对象、边界和方向已经被正式定义。

8. 当前结论

G3-C3 的作用不是立刻建立全量合规体系，而是：

把企业级长期运营阶段中必须长期保留、必须可审计、必须可追责的边界冻结成一份可执行包。

完成 G3-C3 后，下一步最自然的包是： - G3-C4 容量 / 扩展边界包
