G3-C3 审计 / 保留策略真实验证计划

适用阶段：G3 企业级长期运营

用途：把 G3-C3 从“治理对象与边界定义完成”推进到“可执行验证”，明确哪些审计对象、保留方向、权限长期治理和多租户边界可以被实际验证，以及哪些仍只是后续目标。

1. 目标

本计划的目标是：

为 xagent 的审计 / 保留策略包提供第一份真实验证计划，使 G3-C3 不再只停留在定义层，而进入可验证状态。

2. 验证范围

本次验证只覆盖以下内容：

  1. 当前审计对象是否已经明确；
  2. 当前保留方向是否已经可以被区分；
  3. 权限长期治理边界是否已经在现有材料中有真实入口；
  4. 多租户长期边界是否已经被正式表达；
  5. 故障升级与证据升级链是否可以支撑长期审计要求。

本次验证不要求一次性完成： - 完整企业合规体系落地； - 审计系统平台化； - 长期保留策略自动化执行； - 法务/合规外部签字。

3. 验证环境

当前优先采用：

  • 仓库文档与现有证据材料的等价验证环境；
  • 用于确认审计对象、保留方向、权限长期治理与多租户边界是否已形成真实材料基础。

环境前提： - 能读取现有治理材料； - 能读取故障升级路径； - 能读取正式商用检查表中安全/审计/恢复相关条目。

4. 验证项

4.1 审计对象验证

确认以下对象已被列为长期治理对象： - Goal - Task - Run - Workflow - Evidence - Release - 关键发布 / 回滚动作 - 关键配置 / secret / 权限变更动作

期望： - 审计对象不是口头约定，而是已写入包文档； - 可以说清楚哪些对象是长期必须可追的。

4.2 保留方向验证

确认以下方向已存在： - 长期保留对象 - 可清理但需策略的对象 - 不应含糊的保留边界

期望： - 不再是“什么都永久保留”； - 也不是“以后再说”； - 已经形成最小可解释口径。

4.3 权限长期治理验证

确认以下问题已有明确表达： - 权限变更应被记录； - 高风险角色动作需要可回查； - 试点阶段最小权限边界在长期运营中不能倒退； - 绕过默认安全边界的动作必须被审计。

4.4 多租户长期边界验证

确认以下问题已有明确表达： - 多租户数据不可混用； - 证据、run、workflow 的租户回查边界明确； - 哪些异常属于租户隔离事故。

4.5 升级证据链验证

验证 SUPPORT_ESCALATION_PATH_V1.md 是否已提供： - branch / commit / PR - CI run - /health / /ready - docker compose ps - 日志摘录 - 影响范围

期望： - 这些证据足以支撑长期治理中的追责与复盘入口。

5. 通过标准

G3-C3 的真实验证通过，至少需要满足：

  1. 关键审计对象已被真实列出并可复查；
  2. 数据保留方向已不是空白；
  3. 权限长期治理边界已在现有材料中成立；
  4. 多租户长期边界已被明确表达；
  5. 升级 / 故障证据链已足以支撑长期复盘要求。

这意味着： - G3-C3 的“通过”不是完整企业合规已经落地； - 而是长期治理已具备真实可验证的材料基础。

6. 证据要求

本计划要求输出的最小证据包括：

  • 审计对象清单确认结果
  • 保留方向确认结果
  • 权限长期治理边界确认结果
  • 多租户长期边界确认结果
  • 升级 / 故障证据链确认结果
  • 最终判定：
  • 通过 / 不通过
  • 哪些部分已验证
  • 哪些仍是后续目标

建议归档到： - docs/coordination/reports/commercialization-g3-c3-audit-retention-verification.md

7. 当前结论

当前 G3-C3 已完成方向定义； 这份计划的作用是让它进入下一状态：

可执行验证

只有完成这一步，G3-C3 才能从“定义完成”走向“验证完成”。
