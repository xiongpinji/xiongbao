X-Agent Web 全量 UI 重构与视觉差异修复设计说明

1. 文档目的

本文档用于定义 apps/web 第一版桌面端全量 UI 重构方案，并为后续使用 visual-diff-fix 执行视觉差异修复提供统一设计依据。

本次设计目标如下：

  • 以你提供的参考图为方向，采用「英文版结构 + 中文版信息架构」的混合方案。
  • apps/web 内所有可见前端界面统一中文输出。
  • 对现有前端进行激进重构，不受旧入口、旧路由和旧页面组织方式约束。
  • 将通用 AI 平台与创作生产工作台分层设计。
  • 第一版以桌面端为主，同时为后续移动端 App 迁移预留结构边界。
  • 在视觉统一之外，同时提升任务发起、工作区管理、智能体创建和创作执行效率。

2. 总体设计结论

2.1 双层产品结构

前端整体分为两层：

  1. 通用 AI 平台层
  2. 首页
  3. 对话
  4. 会话
  5. 文件
  6. 智能体
  7. 设置
  8. 账户相关入口

  9. 其他管理、浏览、配置型页面

  10. 创作生产工作台层

  11. 创作工作台 / 短剧工厂
  12. 工作流中心
  13. 画布
  14. 编辑器
  15. 其他重交互、重执行、重产物型页面

两层共享同一套视觉语言、中文排版规范和基础组件体系，但页面布局策略不同。

2.2 整体风格定位

产品整体风格定义为：

深色、产品化、现代 AI 平台风格。

其中：

  • 通用 AI 平台层更偏产品首页、列表、卡片、配置中心。
  • 创作生产工作台层更偏专业工具面、状态面、属性面、执行面。

2.3 设计优先级

实现阶段按如下优先级推进：

  1. 全局框架差异修复
  2. 关键页面骨架修复
  3. 创作生产工作台修复
  4. 高光交互与成就时刻补强

3. 第一节：整体信息架构与全局布局骨架

3.1 首页必须升级为工作区入口页

首页不再是单纯欢迎页，也不是单纯输入框页，而是一个真正的工作区总入口。

首页必须支持两类工作区对象：

  • 任务工作区：用于单次目标，例如修复 Bug、实现功能、运行工作流、产出方案。
  • 项目工作区：用于持续性上下文，例如产品改版、客户项目、短剧生产项目、长期研发任务。

核心目标是让用户明确感知：

用户进入的不是一条聊天会话，而是一个独立的任务或项目工作区。

3.2 首页对象模型

首页第一版需要围绕「工作区」组织，而不是围绕「消息」组织。

因此首页至少展示以下对象：

  • 新建任务工作区
  • 新建项目工作区
  • 最近访问工作区
  • 当前活跃工作区
  • 工作区状态
  • 工作区摘要
  • 最近活动

3.3 会话支持自定义命名

每个任务工作区、项目工作区和会话对象都必须支持：

  • 默认自动命名
  • 用户手动重命名
  • 列表中快速改名
  • 进入工作区后顶部改名

命名展示必须以中文为主，不暴露技术 ID，也不让名称被系统内部路由或任务编号主导。

3.4 左下角用户区与设置入口

左下角用户登录信息区域统一简化为身份识别组件。

展示内容仅保留：

  • 用户头像
  • 用户名
  • 套餐等级
  • 一个「设置」按钮

不在该区域展示过多菜单项，也不堆叠账户功能入口。

3.5 设置页入口规则

设置不再作为主业务导航项存在。

点击左下角用户区中的「设置」按钮后，进入一个完整、独立的新设置页面，而不是下拉菜单、局部抽屉或轻量浮层。

这个设置页面本身必须具备：

  • 左侧设置分类导航
  • 顶部返回应用入口
  • 设置搜索能力
  • 完整主内容区域
  • 后续可扩展的系统级分类结构

3.6 主导航规则

左侧主导航只保留核心业务入口。

建议一级导航保留：

  • 首页
  • 对话
  • 会话
  • 文件
  • 智能体
  • 创作工作台
  • 工作流中心
  • 编辑器

设置和账户信息不再与业务入口同级展示。

3.7 会话页职责升级

「会话」页面不再只是聊天历史页，而升级为工作区管理页。

其核心职责包括：

  • 工作区浏览
  • 工作区搜索
  • 类型筛选（任务 / 项目）
  • 状态筛选（进行中 / 已完成 / 挂起）
  • 置顶
  • 归档
  • 重命名
  • 最近更新时间排序

3.8 双层结构的边界

通用 AI 平台层与创作生产工作台层关系如下：

  • 共享设计系统：颜色、排版、按钮、卡片、状态样式、动效节奏一致。
  • 不共享页面骨架：通用平台页偏产品化，创作工作台页偏工具化。

4. 第二节：通用 AI 平台层详细设计

4.1 首页结构

首页由 4 个主区域组成：

4.1.1 顶部主发起区

保留 3 个一级操作：

  • 新建任务工作区
  • 新建项目工作区
  • 继续最近工作

同时提供显眼但不过度突兀的任务输入入口，允许：

  • 输入一句目标
  • 选择创建为任务工作区或挂到项目工作区
  • 创建后直接进入对应工作区

4.1.2 我的工作区

工作区列表以卡片或卡片 + 列表混合形式展示，并区分：

  • 任务工作区
  • 项目工作区

每张卡片至少包含：

  • 工作区名称
  • 类型标签
  • 最近更新时间
  • 最近摘要
  • 当前状态
  • 进入按钮

4.1.3 最近活动

用于展示：

  • 最近对话
  • 最近执行
  • 最近修改
  • 最近工作流记录

4.1.4 推荐能力入口

作为次级内容区展示：

  • 智能体
  • 文件
  • 工作流中心
  • 创作工作台

该区块不与工作区主入口争夺视觉优先级。

4.2 首页层级原则

首页视觉焦点必须分 3 级：

  1. 一级焦点： 今天开始什么工作
  2. 二级焦点： 继续哪个工作区
  3. 三级焦点： 系统还有哪些可调用能力

4.3 工作区卡片设计

工作区卡片统一采用统一卡片系统，但分为两种语义：

4.3.1 任务工作区卡片

重点展示：

  • 当前目标
  • 运行状态
  • 最近输出
  • 快速继续

4.3.2 项目工作区卡片

重点展示：

  • 项目名称
  • 关联任务数
  • 最近活跃内容
  • 项目进展摘要

4.3.3 统一交互能力

所有工作区卡片支持：

  • 点击进入
  • 快速重命名
  • 收藏 / 置顶
  • 展示最近更新时间
  • 展示状态标签

4.4 对话页定位

对话页定义为当前工作区执行面，而不是单纯聊天页。

建议结构如下：

  • 主区：当前目标、消息流 / 执行流、输入区、快捷操作
  • 侧区：当前工作区信息、运行状态、相关文件 / 工具 / 智能体、最近活动

标题展示应优先显示当前工作区名称，而不是技术性路由名称。

4.5 智能体页升级为「市场 + 创建器 + 我的智能体」

智能体页不再只是目录页，而是 3 合 1 页面：

  1. 智能体市场 / 角色目录
  2. 智能体创建器
  3. 我的智能体

4.5.1 内置角色卡

系统提供内置智能体角色卡，例如代码审查专家、前端 UI 助手、API 设计专家、安全顾问、工作流优化专家等。

每张角色卡展示：

  • 头像
  • 名称
  • 定位
  • 能力标签
  • 适用场景
  • 快速选用入口

4.5.2 智能体创建流程

创建流程建议分为 4 步：

  1. 选择来源
  2. 从内置角色卡创建
  3. 从空白创建
  4. 自定义基础信息
  5. 自定义头像
  6. 自定义名字
  7. 一句话定位
  8. 人设信息
  9. 配置能力与用途
  10. 能力标签
  11. 适用任务
  12. 推荐工作区
  13. 是否默认可调用
  14. 预览与保存
  15. 预览角色卡
  16. 确认创建结果

4.5.3 人设信息结构

人设信息不采用单纯大段 Prompt 文本，而采用结构化输入：

  • 角色身份
  • 语气风格
  • 擅长领域
  • 工作原则
  • 禁止事项 / 边界

4.5.4 我的智能体

展示用户已经创建、克隆或改造过的智能体，支持：

  • 编辑
  • 重命名
  • 更换头像
  • 修改人设
  • 删除
  • 归档

4.5.5 智能体创建成功动效

智能体创建成功后采用「工牌签发」动画方案。

动效过程定义为：

  1. 自动生成头像
  2. 头像落位到工牌
  3. 工牌翻转或亮起
  4. 名字显现
  5. 出现「成功入职」完成态

该完成态需要保留短暂停留，以形成可感知的仪式感与高光时刻。

4.6 设置页

设置页作为独立完整页面存在，页面结构如下：

  • 左侧：设置分类导航
  • 顶部：返回应用、搜索设置、当前分类标题
  • 主区：完整设置内容

第一版设置分类建议对齐现有基础：

  • 常规
  • 个人资料
  • 外观
  • 配置
  • 个性化
  • 使用情况和计费
  • MCP 服务器
  • 浏览器
  • 电脑操控
  • Git

实际实现中，可复用现有 SettingsLayout 和设置分区组件，但在视觉和信息组织上需要重构为新设置页面样式。

5. 第三节：创作生产工作台层详细设计

5.1 总原则

创作生产工作台层是独立体系，不与通用平台首页混同。

它需要更强：

  • 操作感
  • 状态感
  • 多面板组织能力
  • 执行流程表达能力

覆盖页面包括：

  • 创作工作台 / 短剧工厂
  • 工作流中心
  • 画布
  • 编辑器

5.2 创作工作台首页

创作工作台不能直接把用户丢进大画布，而应先提供创作项目层。

首页应展示：

  • 当前创作项目
  • 最近打开的创作项目
  • 项目阶段状态
  • 快速新建（新建短剧项目 / 从模板创建 / 继续上次创作）
  • 最近产物
  • 常用节点模板 / 工作流模板

5.3 工作流中心

工作流中心定位为流程控制台，而不是普通表单页。

建议布局：

  • 顶部：工作流名称、状态、保存、运行、审批、发布 / 导出
  • 左侧：节点库、模板、资源入口
  • 中间：工作流主视图
  • 右侧：节点详情、参数、审批状态、运行日志、依赖与产物

页面必须明确展示：

  • 步骤状态颜色
  • 执行中反馈
  • 审批中反馈
  • 成功 / 失败 / 阻塞反馈

5.4 画布页

画布页是高密度交互核心，主任务是搭建、编辑、连接和调整。

布局原则：

  • 主画布区域最大化
  • 侧边工具栏尽量薄
  • 属性编辑在右侧独立面板
  • 顶部操作收敛成一排
  • 底部可承载日志、结果或提示

5.5 编辑器页

编辑器页定位为产物加工台。

可承载内容包括：

  • 时间线
  • 文稿
  • 分镜
  • 媒体片段
  • 输出预览
  • 参数面板

建议结构：

  • 中央：编辑主体
  • 左侧：素材 / 章节 / 结构
  • 右侧：属性 / AI 建议 / 审核意见
  • 顶部：文件名、状态、导出、保存、回退

5.6 与通用平台统一但不混同

创作工作台层与通用平台层统一的内容包括：

  • 中文排版规则
  • 颜色体系
  • 字体层级
  • 按钮、输入框、卡片基础样式
  • 状态标签体系
  • 动效节奏

不统一的内容包括：

  • 面板数量
  • 信息密度
  • 工具型布局优先级
  • 流程状态与属性编辑权重

6. 第四节：统一视觉语言与 TypeUI 优化准则

6.1 视觉气质

整体视觉关键词：

  • 深色
  • 克制
  • 现代
  • 产品化
  • 中文友好
  • 有高级感
  • 有状态感
  • 不花哨但有记忆点

6.2 色彩体系

统一采用深色中性底盘 + 少量品牌强调色。

6.2.1 背景层级

至少建立 4 层背景：

  • App 最外层背景
  • 页面主背景
  • 卡片 / 面板背景
  • 浮层 / 强调面板背景

6.2.2 强调色与状态色

建议：

  • 主强调色：蓝或蓝紫
  • 成功：绿色
  • 警告：橙色
  • 错误：红色
  • 信息：弱蓝

6.3 间距体系

建立统一间距层级：

  • 微间距：图标与文字、标签与标签、标题与副标题
  • 组件内间距：卡片内边距、输入框内边距、列表项高度
  • 区块间距：页面模块之间、左右列模块之间
  • 页面级留白：页面边缘与主内容容器留白

原则是：首页留白更大，工作台页留白让位于操作空间。

6.4 中文排版规则

统一采用中文优先排版策略：

  • 页面标题短、稳、强识别
  • 分区标题明确模块边界
  • 辅助说明尽量控制在 1 至 2 行
  • 标签文字优先使用短词
  • 中文正文行长不宜过长
  • 深色背景下正文对比度必须足够

6.5 组件统一规则

6.5.1 按钮

统一为 4 级：

  • 主按钮
  • 次按钮
  • 弱按钮
  • 危险按钮

6.5.2 卡片

统一为两类：

  • 展示卡片：首页、智能体、项目、工作区
  • 工具卡片：设置、属性面板、状态块

6.5.3 输入框

统一高度、圆角、占位文案颜色、聚焦态、禁用态和错误态。

6.5.4 标签与状态 Chip

统一字号、内边距、背景透明度和颜色语义。

6.5.5 侧边栏

统一选中态、悬停态、图标尺寸、文本字号和分组间距。

6.6 动效体系

动效分为 3 层：

  1. 基础动效：Hover、按压、切换、面板出现、标签变化
  2. 页面动效：页面切换、列表加载、卡片进入、模块展开 / 折叠
  3. 高光动效：智能体创建成功、项目创建成功、工作流运行成功、创作产物完成

原则：

  • 大部分动效必须轻
  • 只有成就时刻才允许明显仪式感
  • 避免全站持续性强动效造成疲劳

6.7 响应式策略

第一版以桌面端为主，但必须为移动端 App 迁移预留结构。

需要预留的迁移边界包括：

  • 首页区块可拆分为独立 section
  • 设置分类可拆为移动端二级列表
  • 工作区卡片可转为纵向列表
  • 智能体创建流程可转为分步表单
  • 创作工作台可拆为底部 Tab + 二级详情页

6.8 页面一致性检查项

每个页面改造后都必须检查：

  1. 是否只有一个主视觉焦点
  2. 是否有清晰标题、说明、主体、辅助区
  3. 是否使用统一按钮体系
  4. 是否使用统一卡片体系
  5. 中文文本是否易读
  6. 状态颜色是否统一
  7. 页面留白是否合理
  8. 是否保留最重要的操作空间

6.9 visual-diff-fix 执行优先级

使用 visual-diff-fix 时，按照以下优先级修复：

  1. 全局框架差异
  2. 导航
  3. 顶栏
  4. 页面宽度
  5. 背景层次
  6. 设置入口
  7. 用户区
  8. 首页骨架
  9. 关键页面骨架
  10. 首页
  11. 对话页
  12. 会话页
  13. 智能体页
  14. 设置页
  15. 独立工作台体系
  16. 创作工作台
  17. 工作流页
  18. 画布页
  19. 编辑器页
  20. 高光体验
  21. 智能体创建成功动画
  22. 状态反馈
  23. 关键操作成就感

7. 与当前代码结构的映射说明

当前 apps/web 已存在的主要页面与组件包括：

  • 页面：HomePage.tsx、SessionsPage.tsx、ChatPage.tsx、AgentsPage.tsx、SettingsPage.tsx、AccountPage.tsx、CreativeStudioPage.tsx、WorkflowsPage.tsx、CanvasPage.tsx、EditorPage.tsx、FilesPage.tsx
  • 布局：AppShell.tsx、WorkspaceSidebar.tsx、TopBar.tsx
  • 设置：SettingsLayout.tsx 与各设置分区组件

本次改造不要求保留现有页面语义和布局方式，但应尽量复用：

  • 已有页面职责映射
  • 已有设置分区功能
  • 已有工作流、创作、对话数据流

9. 验收标准

当以下条件成立时，可视为本轮 UI 设计目标达成：

  1. apps/web 所有可见界面完成中文化统一。
  2. 首页成功升级为工作区入口页。
  3. 任务工作区与项目工作区模型明确可见。
  4. 会话页完成向工作区管理页的职责升级。
  5. 智能体页完成从目录页到市场 + 创建器 + 我的智能体的升级。
  6. 设置入口统一收敛到左下角用户区中的单一设置按钮。
  7. 设置页成为完整独立的新设置页面。
  8. 创作生产工作台层与通用平台层在视觉上统一、在结构上区分。
  9. 智能体创建成功后的工牌签发动效落地。
  10. visual-diff-fix 可据此文档对全局、关键页和高光交互进行有序修复。
