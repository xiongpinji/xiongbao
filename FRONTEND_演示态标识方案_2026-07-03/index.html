前端“预览 / 演示态”标识方案（2026-07-03）

目标：减少用户误解，明确哪些页面当前是“真实执行入口”，哪些页面仍是“预览 / 导航 / 本地回显辅助”。

1. 标识原则

当前前端改动引入了大量 ConversationalCommand 入口。视觉上它们都像“智能助手”，但并不是每一个都会触发真实后端执行。

因此需要统一规则：

  • 真实执行入口： 不额外标“预览”，但要让用户知道会触发什么。
  • 本地回显 / 导航辅助： 必须标“预览”或“辅助”。
  • fallback 演示数据： 必须明确写出“当前显示的是本地预览数据”。

建议统一采用以下 3 种标签之一：

  • 预览态
  • 辅助模式
  • 本地演示数据

2. 优先需要补标识的页面

2.1 AgentsPage

文件： src/pages/AgentsPage.tsx

原因： - 接口失败时会展示 fallbackRoles - 页面视觉上像“真的能切换多个专业智能体并调度”

建议标识位置： - 页面主标题下方说明区 - fallback 提示框中保留更明确措辞

建议文案：

默认提示（可长期保留）

当前页用于浏览和预览智能体角色，角色调度入口仍以真实后端能力为准。

fallback 提示（接口失败时）

后端角色接口暂不可用，当前展示的是本地演示角色，仅用于 UI 预览，不代表真实可调度角色集合。

2.2 MemoryPage

文件： src/pages/MemoryPage.tsx

原因： - 当前“记忆检索助手”主要是整理意图、给建议、跳配置页 - 并不直接返回真实知识库命中结果

建议标识位置： - ConversationalCommand 上方增加一行细说明 - 或在 header 段落后增加一个小提示卡片

建议文案：

当前为检索意图整理与导航辅助模式，不直接展示真实知识库结果。实际检索仍需进入索引库或后端检索链路。

2.3 OpenSourcePage

文件： src/pages/OpenSourcePage.tsx

原因： - 当前“开源比选助手”主要做目标整理与策略建议 - 用户容易误以为已经在实时搜索仓库

建议标识位置： - header 段落后 - ConversationalCommand 组件上方或下方

建议文案：

当前为开源比选预览入口，优先整理能力缺口与比选目标，不直接返回实时仓库搜索结果。

2.4 SettingsLayout 中的“配置助手”

文件： src/components/settings/SettingsLayout.tsx

原因： - 当前主要生成配置检查建议 - 不会真实写入配置

建议标识位置： - ConversationalCommand 上方 - 或组件内部标题旁边增加小标签

建议文案：

配置助手当前用于生成检查清单与调整建议，不会直接修改本地或远端配置。

2.5 ShellContextPanel 中的“上下文助手”

文件： src/components/layout/ShellContextPanel.tsx

原因： - 当前更像“上下文建议器” - 不应被误解为当前页的真实执行代理

建议标识位置： - ConversationalCommand 上方 - 或标题右上角加一个“辅助”标签

建议文案：

当前为上下文辅助助手，优先提供总结、建议与跳转，不直接执行后台任务。

3. 可选补标识的页面

3.1 Run Console 的“运行分析助手”

文件： src/components/runs/RunConsole.tsx

原因： - 当前回答主要基于已有 RunDetail 做本地总结 - 若未真正调用后台分析，则应避免被理解成“深度诊断代理”

建议文案：

当前为基于运行详情的本地分析视图，优先帮助你快速梳理 Timeline、Evidence 和 Artifacts。

3.2 WorkflowsPage 的“工作流编排助手”

文件： src/pages/WorkflowsPage.tsx

原因： - 当前输入主要写入页面局部状态并新增步骤 - 不等于已经进入正式后端编排

建议文案：

当前优先生成页面内步骤草案；正式执行仍以“创建并执行”按钮触发的后端工作流为准。

3.3 CreativeStudioPage 中的对话式入口

文件： src/pages/CreativeStudioPage.tsx

原因： - 如果当前更多是在页面侧生成草案 / 节点意图，而不是所有输入都立即触发真实后端 - 建议明确区分“草案”和“执行”

建议文案：

当前输入优先生成创作草案与页面节点意图；正式生产链路仍以明确的执行按钮和后端返回结果为准。

4. 不建议补“预览态”标识的页面

以下页面当前更接近真实主入口，不建议泛化为“预览”，避免削弱可信度：

4.1 LoginPage

  • 登录与匿名进入是实际入口，不是演示页。

4.2 ChatPage

  • 即使内部有 SSE fallback，它仍是主执行入口。
  • 不应标成“预览态”。

4.3 ProfessionalModePage

  • 这是导航聚合页，不是助手预览页。
  • 可说明“模式入口”，但不应一概标预览。

4.4 AppShell / 顶层壳层

  • 属于产品框架层，不需要“预览”标签。

5. 标识样式建议

为了不把页面搞得太重，建议统一用轻提示，不要做成大块 warning。

样式建议 A：细说明文字

适合：Memory / Open Source / Settings

当前为导航辅助模式，不直接执行真实检索。

样式建议 B：小标签 + 一句话

适合：ShellContextPanel / Run Console

辅助模式
当前为上下文辅助助手，优先提供建议与跳转。

样式建议 C：fallback 提示框

适合：AgentsPage

当前展示的是本地演示数据，仅用于 UI 预览。

6. 推荐落地顺序

建议按误导风险从高到低补：

  1. AgentsPage
  2. MemoryPage
  3. OpenSourcePage
  4. SettingsLayout
  5. ShellContextPanel
  6. RunConsole
  7. WorkflowsPage
  8. CreativeStudioPage

7. 最小落地标准

如果本轮时间有限，至少补完前 5 项：

  • AgentsPage
  • MemoryPage
  • OpenSourcePage
  • SettingsLayout
  • ShellContextPanel

只要这 5 个补齐，就能显著降低“用户把辅助入口误解为真实智能执行”的风险。
