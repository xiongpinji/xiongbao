研发效能变体 · 对外口径页

面向研发团队客户的表述规范。所有口径以 docs/COMMERCIAL_STATUS_SOURCE_OF_TRUTH.md（SOT）为唯一事实源，本页不得与其冲突。

1. 可以这样说

  • "面向研发团队的 AI 工程效能平台：代码评审 API、仓库级 AGENTS.md 分层指令、企业级权限与审计。"
  • "代码评审支持 diff 直传与 repo+base..head 两种输入，结果可回查（POST/GET /api/v1/code-review）。"
  • "AGENTS.md 分层指令与 Codex 语义对齐：用户级 < 工作区根 < 子目录级，冲突时深层覆盖浅层，合并时标注来源层级。"
  • "权限模型为资源:动作粒度（如 code_review:execute/read），可对接企业 SSO/OIDC（full 模式 Keycloak）。"
  • "已达到 SOT 定义的正式商用可交付口径（G1/G2/G3 全闭环）。"

2. 不建议这样说（沿用 SOT §6.2）

  • 不说"完全替代 Codex/人工评审"——定位为效能增强与第一道防线；
  • 不说"多机 HA 已验证"——共享状态与数据一致性为同机两实例实测；
  • 不说"支持任意私有部署形态"——K8s/Helm 已产品化，但客户现场集群级演练未做；
  • 不说"评审结果零误报"——LLM 评审存在固有误报率，演示用真实 diff 不承诺指标。

3. SOT 不可宣称项核对（建包日 2026-08-04）

不可宣称项 本变体口径处理
多机 HA / Redis 自身高可用 不提；被问及时答"同机两实例已实测，多机演练在路线图中"
L2 E2B 云沙箱 不提（无 key 未实测）
非当前机器目标环境演练 不提；交付走试点包 Gate 流程
lite 模式账号体系 研发效能变体一律按 full 模式（Keycloak）交付，规避 lite 内存 UserStore 不跨实例缺口

4. 行业化文案槽位（客户落地时替换）

  • 产品名：X-Agent 研发效能版（可冠客户名）
  • 案例：试点期产出的评审采纳率、AGENTS.md 覆盖仓库数（试点包验收时回填）
