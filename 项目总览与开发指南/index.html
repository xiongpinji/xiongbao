X-Agent 项目总览与开发指南（重构版）

本文件是 X-Agent 开源重构版的功能版图与历史开发入口。当前发布 / 商用 readiness 判断以 COMMERCIAL_STATUS_SOURCE_OF_TRUTH.md 为准。 维护约定：每完成一个阶段 / 重大调整，更新「开发进度」与「变更记录」两节。

  • 文档版本：v1.0
  • 最后更新：2026-07-06
  • 对应代码版本：xagent 0.1.0（历史功能版图 + readiness 证据收口中）

说明：本文保留 2026-06 历史验收记录，其中“全部完成 / 商用交付 / 生产就绪”等表述均为当时阶段验收口径，不等同于 2026-07-06 当前正式商用 GA 或发布签字。

1. 项目是什么

X-Agent —— 面向企业的自主智能体框架（开源重构版）。

这是对老 X-Agent（../X-Agent/，740+ 后端 core 文件、严重重复造轮子）的全新净重写。核心理念一句话：

编排内核 + 适配层 + 独有语义 —— 不重复造轮子，成熟能力交给生产级开源组件，X-Agent 只保留并强化自己的差异化资产。

1.1 重写动机（来自旧仓审计结论）

  • 旧仓 core/ 共 740 个 .py，其中约 137 个是 AI 自生成的过程产物（codex_*_readiness_packet.py / integration_review_*.py），零业务逻辑。
  • 每个能力域都有 v2 / optimized / enhanced / complete 多版本并存（记忆 19、agent 19、技能 26、插件 16、开源发现 20…）。
  • 多份审计确认：RC 非 GA，企业模块/MCP HTTP/多模态/创意工厂多为内存实现或占位；安全审计发现 30+ 越权漏洞集中在 api/。

1.2 四大护城河（必须保留并强化）

  1. 工作流结构化视图（timeline / compensation / panels）
  2. 短剧工厂（无限拖拽画布 + 智能体生成全节点链 + 每节点人工审核/修改 + 出图出视频 + 视频剪辑引擎）
  3. 开源候选发现（多源聚合 + 打分，开源界无直接对标）
  4. 多租户审计黑板（防篡改审计链）

1.3 决策基线（已与 owner 确认）

维度 决策
形态 全新干净仓库净重写，独有资产移植，底座全换开源
范围 全功能一次到位（15 大能力域全覆盖）
部署 单机(Docker Compose)/Tauri 桌面优先，K8s/HA 留接口后做
基座 OSS 对标计划推荐组合（全 MIT/Apache，避开 AGPL/GPL/ELv2）
媒体生成 云 AI 生成 API（LibLib/LibTV 风格），不自托管 ComfyUI

7 项升级任务

升级 1：DeerFlow 2.0 替代纯 LangGraph（编排底座）

  • 仓库：https://github.com/bytedance/deer-flow（72.2k★ MIT）
  • 为什么：DeerFlow 是 LangGraph 之上的完整超级智能体框架——主 agent 动态派发子 agent 并行、Docker 沙箱、持久化记忆、Markdown 技能系统、IM 通道，比自建上层省巨量代码
  • 做法：pip install deer-flow，用嵌入模式作编排内核；保留 X-Agent 路由/鉴权/独有域不变
  • 影响：core/orchestration/ 层替换为 DeerFlow 驱动；run_agent 接口保持不变（适配器模式）

升级 2：Hatchet 替代内存工作流引擎

  • 仓库：https://github.com/hatchet-dev/hatchet（7.4k★ MIT）
  • 为什么：Hatchet 专为 AI agent 持久工作流设计，比 Temporal 轻量（不需独立集群），原生支持持久化/重试/超时/优先级/并发控制
  • 做法：pip install hatchet-sdk，工作流步骤改为 Hatchet step
  • 影响：core/workflow/engine.py 后端切 Hatchet；保留 view model / timeline 前端展示

升级 3：Composio 工具后端接入

  • 仓库：https://github.com/ComposioHQ/composio（28.9k★ MIT）
  • 为什么：1000+ SaaS 工具 + OAuth 认证管理，专为 agent 工具后端设计，原生 MCP Server 支持
  • 做法：pip install composio-core，注册到现有 ToolRegistry
  • 影响：adapters/tools/ 新增 composio_provider.py；现有内置工具继续保留

升级 4：IBM ContextForge MCP 网关

  • 仓库：https://github.com/IBM/mcp-context-forge（3.9k★ Apache）
  • 为什么：生产级 MCP 网关——联邦多 server、认证/限流/OTel、REST/gRPC→MCP 协议翻译
  • 做法：compose 加 ContextForge 服务；adapters/mcp/client.py 改为调网关 HTTP API
  • 影响：adapters/mcp/ 升级为网关模式；compose 加一个容器

升级 5：OpenFGA 细粒度授权

  • 仓库：https://github.com/openfga/openfga（5.3k★ Apache，CNCF 沙箱）
  • 为什么：Google Zanzibar 模型，天然适合多租户关系型授权（tenant→org→team→user→agent→resource）
  • 做法：pip install openfga-sdk，部署 OpenFGA 服务；加 openfga_enforcer.py
  • 影响：保留内置 RBAC 做降级；full/enterprise 模式走 OpenFGA

升级 6：Promptfoo CI 评测门禁

  • 仓库：https://github.com/promptfoo/promptfoo（22.4k★ MIT，被 OpenAI/Anthropic 使用）
  • 为什么：CLI 原生 CI/CD，同时覆盖质量评测 + 红队安全扫描
  • 做法：npm install -g promptfoo，加 .promptfoo/ 配置 + CI workflow step
  • 影响：.github/workflows/ci.yml 加评测 step；不影响代码

升级 7：LightRAG 文档知识库

  • 仓库：https://github.com/HKUDS/LightRAG（36.8k★ MIT，EMNLP 2025）
  • 为什么：轻量图+向量双层 RAG，5 种检索模式，支持 Qdrant 后端，补充文档知识检索能力
  • 做法：pip install lightrag-hku，新建 adapters/knowledge/ 适配层
  • 影响：在 Mem0（会话记忆）+ Graphiti（图谱记忆）基础上补充文档知识检索

执行顺序

升级 1 (DeerFlow 编排) → 升级 2 (Hatchet 工作流) → 升级 3 (Composio 工具)
→ 升级 4 (ContextForge MCP) → 升级 5 (OpenFGA 授权) → 升级 6 (Promptfoo 评测)

每步可独立验收，前后无强依赖。许可证全部 MIT/Apache-2.0，CI license-check 可通过。

4.1 前端重构方向：ZCode 风格工作台 + 短剧工厂自由画布

2026-06-22 起，前端进入新一轮产品级重构，目标从“多页面工作台”升级为 ZCode 风格暗色折叠 AI 工作台：

  • 主导航默认折叠：保留新建任务、搜索、技能、对话、智能体、短剧工厂、工作流、设置；最大化主工作区。
  • 预留工作区 / 项目区 / 对话区：项目、任务、对话、短剧画布围绕当前工作区组织。
  • 开源发现与知识库迁入设置页：统一放入 设置 -> 索引库，作为能力配置和索引管理入口，不再占用主导航。
  • 视频剪辑合并进短剧工厂：剪辑能力成为短剧工厂自由画布中的「剪辑节点」和「导出节点」；/editor 仅保留为高级剪辑兼容入口。
  • 短剧工厂自由画布工作流化：继续使用 React Flow 作为画布底座；所有短剧流程在画布节点中建立，节点连线对齐 WorkflowEngine depends_on，节点审核对齐 ApprovalGate，产物以 artifact 统一展示。
  • 多会话协作推进：以 docs/coordination/ 为总控协作目录，通过 handoff/report 机制组织前端工作台、设置索引、短剧画布、后端工作流、剪辑导出、验证、审计、交付文档等专属会话。

本轮详细设计见：docs/frontend-zcode-workbench-refactor.md；实施计划见：docs/superpowers/plans/2026-06-21-zcode-workbench-short-drama-canvas.md；多会话调度见：docs/coordination/。

5. 运行模式

模式 XAGENT_MODE 说明 依赖
lite lite 单机/桌面/演示。SQLite + 内存缓存 + Qdrant 内存 + 内置 JWT + mock LLM 降级 无需 Docker
full full 单机生产/试点。Postgres + Redis + Qdrant + Langfuse + LiteLLM + Keycloak docker-compose
enterprise enterprise 多区域 HA（后做） K8s / Helm

模式由 settings 控制；各 adapter 工厂据此选具体实现或优雅降级（无 key/无服务时不报错，走 mock/noop/内存）。这是"单机优先"能跑通的关键。

6. 开发约定

6.1 适配器契约模式（强约束）

core / domains 只 import adapters.<name> 暴露的 Protocol 抽象与工厂，绝不直接 import 具体开源库。每个 adapter 子包：

base.py     —— Protocol 抽象 + 数据类型
<impl>.py   —— 具体开源实现（如 litellm_client.py）
null/mock   —— lite/测试降级实现
factory.py  —— get_xxx() 据 settings 返回实例（lru_cache 单例 + reset_xxx 供测试）

6.2 配置

  • 全部走 infra/settings.py，环境变量前缀 XAGENT_，嵌套用 __（如 XAGENT_LLM__PROXY_URL）。
  • 生产模式启动时 validate_for_production() 硬校验（禁 CORS *、禁默认 JWT secret、禁关鉴权）。

6.3 安全默认

  • 所有业务端点默认要求 principal（认证主体）+ 租户隔离（Phase 1 接入）。闭合旧仓 30+ 越权。
  • 媒体/外部生成走 HTTP API，不本地链接 GPL 代码。

6.4 许可证红线（CI license-check 拦截）

🔴 禁止：AGPL（Skyvern/Daytona）、GPL 直接链接（不自托管 ComfyUI）、ELv2（Arize Phoenix）、Source-Available（n8n/Pipedream）。 🟢 优先：MIT / Apache-2.0 / BSD。

6.5 代码风格

  • ruff（line-length 100）+ mypy + pytest（asyncio_mode=auto）。
  • 注释/文档用中文，与团队习惯一致；docstring 说"为什么"，不复述"是什么"。

6.6 CodeGraph 代码知识图谱（开发期必备）

本项目已用 CodeGraph（v0.9.x，.codegraph/codegraph.db）建立代码知识图谱，文件监听自动同步。开发时配合使用，避免大范围盲搜、保证改动影响可控：

codegraph status   "<xagent路径>"          # 查看索引状态/统计
codegraph sync     "<xagent路径>"          # 手动同步（通常自动）
codegraph query    <符号>                  # 按符号检索定义
codegraph callers  <符号>                  # 谁调用了它（改前看上游）
codegraph callees  <符号>                  # 它调用了谁
codegraph impact   <符号>                  # 改它会影响哪些代码
codegraph affected <改动文件...>           # 受影响的测试文件

约定： - 改某个符号/适配器前先 codegraph impact/callers 评估影响面。 - 新增模块后图谱会自动 sync；若 CI 或查询前不确定，先 codegraph sync。 - 适配器契约（§6.1）的依赖倒置可用 callers/callees 校验：core/domains 不应直接指向具体开源库实现，只指向 adapters.* 工厂与 Protocol。
