前端页面验收执行版（2026-07-03）

适用范围：apps/web 当前未提交改动。 目标：把“收口清单”变成可直接执行的页面点击验收单。 执行前提：

  • 后端可访问：http://127.0.0.1:8000
  • 前端可访问：http://127.0.0.1:3000
  • 当前已确认 typecheck 与 build 通过

1. 验收记录模板

每个页面按同一格式记录，避免只记“好像有问题”：

  • 步骤： 点了什么、输入了什么。
  • 预期： 应该看到什么。
  • 实际： 实际出现了什么。
  • 结果： 通过 / 不通过 / 待确认。
  • 备注： 截图路径、报错文案、接口状态码。

建议记录成下面格式：

### 验收项：登录后跳转
- 步骤：输入 admin / admin，点击“登录”
- 预期：跳转到 /chat
- 实际：跳转到 /chat，页面正常显示
- 结果：通过
- 备注：无

2. 启动前准备

2.1 启动后端

在 apps/api 目录执行：

xagent serve

2.2 启动前端

在 apps/web 目录执行：

npm run dev

2.3 启动后先做 3 个快速确认

  • [ ] 打开 http://127.0.0.1:8000/health，看到 status=ok
  • [ ] 打开 http://127.0.0.1:3000，页面可加载
  • [ ] 如走登录模式，确认 admin / admin 可登录

3. 第一轮：登录与进入路径

目标：先确认“进得去”。如果第一轮不稳，不要继续验深层页面。

3.1 登录页

入口： /login

  • [ ] 页面加载后，确认 Logo、标题、输入框、按钮样式正常。
  • [ ] 用户名为空、密码为空时，登录按钮应不可用。
  • [ ] 输入用户名但不输入密码时，登录按钮仍不可用。
  • [ ] 输入用户名密码后，登录按钮应可点击。

记录重点： - 是否有布局错位 - 是否有按钮状态错误 - 深色背景下文字是否可读

3.2 正常登录

步骤： 1. 输入 admin 2. 输入 admin 3. 点击“登录”

预期： - 跳转到 /chat - 不停留在 loading - 不显示错误提示

失败时记录： - 是否出现错误提示 - 错误提示具体文案 - 后端日志是否有 /auth/login 失败

3.3 匿名进入

步骤： 点击“匿名进入工作区”

预期： - 跳转到 /chat - 页面正常可见 - 刷新后仍处于工作区，而不是被踢回登录页

额外检查： - [ ] 匿名进入后直接访问 /agents - [ ] 匿名进入后直接访问 /professional?mode=workflow - [ ] 匿名进入后直接访问 /runs/不存在的id

记录重点： - 哪些页面匿名可进 - 哪些页面匿名会 401 或 fallback

4. 第二轮：路由兼容与 Professional Mode

目标：确认新导航模型没有把旧入口搞坏。

4.1 旧入口跳转

依次在浏览器直接访问：

  • [ ] /workflows
  • [ ] /creative
  • [ ] /canvas
  • [ ] /home

预期： - /workflows → /professional?mode=workflow - /creative → /professional?mode=drama - /canvas → /professional?mode=drama - /home → 等价进入 /chat

记录重点： - 地址栏是否真的变化 - 页面是否对应正确模式 - 跳转后是否有白屏或短暂闪烁

4.2 Professional Mode 双模式切换

入口： /professional?mode=drama

执行： - [ ] 点击切到 workflow - [ ] 再切回 drama - [ ] 带上 workspace 参数后再切换一次

预期： - 顶部模式 tab 激活态正确 - 主内容区切换正确 - 没有整页刷新感 - 不出现空白内容区

记录重点： - mode 切换是否丢查询参数 - 页头 / 右侧上下文是否同步变化

4.3 高级剪辑入口

入口： Professional Mode 页头中的“高级剪辑”

  • [ ] 点击后能进入 /editor
  • [ ] 从 /editor 返回主要工作区路径是否顺畅

5. 第三轮：核心执行链路

目标：先验“主链路能走”，再看辅助页。

5.1 Chat 页

入口： /chat

用例 A：空输入

  • [ ] 输入框为空时，“发送”按钮应不可用。

用例 B：普通任务提交

  • [ ] 输入一句简单任务，例如“写一个函数”
  • [ ] 点击发送

预期： - 出现用户消息气泡 - 出现“正在分析任务并调用 Agent...”状态 - 若 SSE 成功，应显示流式结果或最终结果 - 若 SSE 失败，应回退到普通 runAgent - 成功后出现“查看运行详情”按钮

记录重点： - 是走了 SSE 还是 fallback - 错误提示是否可读 - 是否拿到了 runId

用例 C：运行详情跳转

  • [ ] 点击“查看运行详情”
  • [ ] 确认进入 /runs/:runId

5.2 Workflow 页

入口： /professional?mode=workflow

用例 A：手动新增步骤

  • [ ] 点击“添加步骤”
  • [ ] 确认步骤列表新增一项
  • [ ] 确认画布中新增一个节点

用例 B：对话助手新增步骤

  • [ ] 在“工作流编排助手”里输入一句，例如“增加人工审批节点”
  • [ ] 确认步骤列表新增
  • [ ] 确认画布节点同步新增

用例 C：删除步骤

  • [ ] 删除某个步骤
  • [ ] 确认列表项消失
  • [ ] 确认节点与相关边也消失

用例 D：创建并执行

  • [ ] 至少保留 1 个有目标的步骤
  • [ ] 点击“创建并执行”

预期： - 无前端报错 - 若后端成功返回，跳转 /runs/:runId - 若失败，应有可见错误提示

5.3 Creative / Drama 页

入口： /professional?mode=drama

用例 A：创建画布

  • [ ] 输入 brief
  • [ ] 点击创建或等价操作
  • [ ] 确认节点生成、画布更新

用例 B：执行 produce

  • [ ] 触发生产流程
  • [ ] 观察 loading、错误提示、结果区
  • [ ] 若成功，确认是否跳转到运行详情页

用例 C：节点编辑 / 时间线相关入口

  • [ ] 点击节点
  • [ ] 检查右侧或详情区域是否响应
  • [ ] 若有 timeline / editor 入口，检查是否可进入

记录重点： - 失败时错误提示是否明确 - 成功后 runId / timelineId 是否合理

5.4 Run Detail 页

用例 A：有效 runId

  • [ ] 从 Chat / Workflow / Creative 成功跳转进入
  • [ ] 检查 Run Console 是否完整渲染
  • [ ] 检查 Timeline / Evidence / Artifacts 面板能展开

用例 B：无效 runId

  • [ ] 手工输入一个不存在的 runId
  • [ ] 确认进入 fallback 页，而不是白屏

用例 C：缺少 runId

  • [ ] 访问异常路径或构造无参数场景
  • [ ] 确认 fallback 文案合理

用例 D：fallback 动作

  • [ ] 点击“重试”
  • [ ] 点击“返回对话”
  • [ ] 点击“打开工作流”

记录重点： - fallback 页是否清晰说明问题 - 按钮动作是否都真的可用

6. 第四轮：壳层与布局验收

目标：确认“新壳子好不好用”，而不只是“能不能显示”。

6.1 左侧 Rail

  • [ ] 所有图标可点击
  • [ ] 当前页高亮正确
  • [ ] hover 态明显
  • [ ] Logo 显示正常

6.2 Workspace Sidebar

  • [ ] 展开态下内容完整
  • [ ] 点击折叠按钮后收起
  • [ ] 收起后可再次展开
  • [ ] “新建会话 / 技能 / 专业模式 / 智能体角色”入口可点击

6.3 右侧 Context Panel

  • [ ] 在大屏 (xl) 下可见
  • [ ] Recent sessions 区块不空白错位
  • [ ] 上下文助手输入框样式正常
  • [ ] Past actions 区块在无数据时展示合理

6.4 TopBar

  • [ ] 大屏下菜单按钮不重叠
  • [ ] 小屏下标题区不挤压
  • [ ] Pro / Bell / profile 类按钮显示正常

6.5 视觉可读性

对以下内容做肉眼检查：

  • [ ] 输入框 placeholder 是否够清楚
  • [ ] 次级说明文字是否过暗
  • [ ] 黑金主题下边框层级是否可辨认
  • [ ] 按钮 hover / disabled 状态是否明确
  • [ ] 长内容区域滚动条是否可见且不突兀

7. 第五轮：辅助 / 演示页面验收

目标：确认这些页面至少“不会误导、不会崩”。

7.1 AgentsPage

  • [ ] 后端可用时，真实角色能否正常显示
  • [ ] 后端不可用时，fallback 角色是否显示
  • [ ] 是否有明确提示“当前展示的是本地预览角色”

7.2 MemoryPage

  • [ ] 对话助手可输入
  • [ ] 点击“打开知识库配置”后，能进入 settings?section=index&tab=knowledge
  • [ ] 页面文案不会让用户误以为这里已直接显示真实检索结果

7.3 OpenSourcePage

  • [ ] 对话助手可输入
  • [ ] 点击“打开开源发现配置”后，能进入 settings?section=index&tab=open-source
  • [ ] 页面文案不会让用户误以为这里已直接返回实时仓库结果

7.4 SettingsPage

  • [ ] section 切换正常
  • [ ] “配置助手”可输入
  • [ ] 不会给人“已经真实改了配置”的误解

8. 问题分级规则

验收时，把问题分成 3 类，避免所有问题都堆成一团。

阻断

满足任一项：

  • 页面打不开 / 白屏
  • 主链路无法走通
  • 登录或路由跳转失效
  • 点击关键按钮无反应且无提示
  • 匿名 / 登录态把用户卡死在错误状态

非阻断

满足任一项：

  • 文案误导
  • fallback 提示不清楚
  • 某些次级入口行为不顺
  • 样式错位但不影响主流程

后续优化

满足任一项：

  • chunk 过大 warning
  • 视觉细节可再打磨
  • 演示态标识可增强
  • 静态假数据后续接真数据

9. 建议的执行顺序（最省时间版本）

如果时间有限，按下面顺序走：

  1. 登录页
  2. 匿名进入
  3. /workflows / /creative / /canvas 跳转
  4. Chat 提交一次任务
  5. 打开 Run Detail
  6. Professional Mode 的 workflow / drama 切换
  7. Workflow 新增步骤 + 执行
  8. Creative 创建 brief + 运行
  9. Agents / Memory / OpenSource / Settings 做快速冒烟

10. 执行后输出建议

建议验收结束后，产出一份简短结论，格式如下：

## 前端验收结论

### 通过
- 登录 / 匿名进入正常
- Professional Mode 路由兼容正常
- Chat → Run Detail 主链正常

### 阻断问题
- xxx

### 非阻断问题
- xxx

### 后续优化
- chunk 体积较大
- 演示态标识需补齐

这样后续就能直接进入“修问题 / 拆提交 / 补标识”阶段。
