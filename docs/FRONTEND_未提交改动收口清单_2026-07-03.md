## 3. 需要补“预览 / 演示态”标识的页面

> 原则：凡是 UI 看起来像“真实智能助手”，但当前主要做本地回显、导航辅助、fallback 展示的，都应该明确标注。

### 优先补标识的页面

#### A. AgentsPage

**原因：**
- 接口失败时会展示 fallbackRoles。
- 页面看起来像可以真正调度多个智能体。

**建议文案：**
- “当前为角色预览模式”
- “当后端角色接口不可用时，展示本地演示角色”

#### B. MemoryPage

**原因：**
- 当前对话助手主要是导航与建议，不是真正返回检索结果。

**建议文案：**
- “当前助手用于引导检索流程，不直接展示真实知识库结果”
- 或 “预览态：此处主要用于整理检索意图并跳转配置页”

#### C. OpenSourcePage

**原因：**
- 当前是意图收集与策略建议，不是实时仓库检索结果页。

**建议文案：**
- “当前为开源比选助手预览”
- “输入内容将先整理为比选目标，不直接返回实时候选仓库”

#### D. SettingsLayout 中的“配置助手”

**原因：**
- 当前主要返回检查清单，不会真实改配置。

**建议文案：**
- “仅生成配置检查建议，不会直接写入设置”

#### E. ShellContextPanel 的“上下文助手”

**原因：**
- 更偏 UI 辅助入口，不应被理解为当前页的真实智能代理。

**建议文案：**
- “当前为上下文辅助助手，优先提供建议与跳转，不直接执行后台任务”

### 可选补标识的页面

#### F. Run Console 中的“运行分析助手”

如果它当前只是基于 `RunDetail` 本地总结而非真实调用后台分析，可补一句：

- “基于当前运行详情的本地分析视图”

#### G. Workflow / Creative 的对话助手

如果它们现在只是把输入写入页面局部状态，而不是正式进入后端编排，可补一句：

- “当前优先生成页面内步骤草案，执行仍以按钮操作为准”
