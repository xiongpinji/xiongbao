# Web/API R1 发布审计执行计划

## 目标与边界

对 `feature/webapi-release-hardening` 的当前冻结候选执行可复现发布审计。只对 Web/API、编排、开发任务、调度、技能、checkpoint 与 Platform MCP 形成发布结论；短剧、Tauri 桌面、多机 HA、E2B 和客户现场演练继续排除。

## 成功标准

1. 工作树无未提交变更，API/Web/README/tag 版本一致，CI release 只在全部依赖 gate 成功后执行。
2. 后端全量或明确 Web/API 范围测试通过；任何超时、跳过和排除均单独记录，不能写成通过。
3. Web 默认单测、lint、typecheck、production build 和关键真实浏览器链通过。
4. Ruff/mypy 不反弹；残留问题按精确 finding 形成有 owner、理由、范围和失效日期的临时豁免，不只保存总数。
5. 生产依赖漏洞、许可证、配置、明文 secret、空库迁移和 Docker/发布配置完成审计；高危未处置项阻断发布。
6. 从登录到会话/run，再到调度、开发任务、技能包、checkpoint 的关键 Web/API 页面使用独立数据库和真实服务完成同链验证。
7. 发布物、升级与回滚边界有可执行证据；不创建或移动正式 tag，不向远端推送，不宣称排除能力已发布。

## 执行顺序

1. 冻结候选与版本/CI/范围审计。
2. 后端全量、关键静态、迁移、许可证和依赖安全检查。
3. Web 安装、单测、lint、typecheck、build 和生产依赖审计。
4. 独立 SQLite + API + Web 的真实浏览器主链与后端回读。
5. 质量豁免逐项落盘并用自动门禁校验不漂移。
6. 复跑所有发布 gate，生成 R1 最终证据；只有无阻断项时才把任务转 Done。

## 失败处理

- 测试先记录失败命令、错误和影响面，再做最小修复并重跑相关链。
- 网络、Docker、可选依赖或 Windows 路径造成的环境限制单列，不能用阈值或跳过掩盖。
- 若高危漏洞、数据迁移、真实认证或核心同链仍失败，R1 保持进行中并给出明确阻断项。
