# X-Agent 全量商用交付整改设计

## 1. 目标

将当前仓库整改到可验证的商用交付标准。整改完成必须同时满足：

1. Web/API、短剧、Tauri 桌面端分别通过独立交付门禁。
2. 版本、安全、依赖、镜像、CI 与证据治理使用同一套共享门禁。
3. 同一候选 SHA 上完成源码检查、测试、构建、隔离运行时、真实本地模型、浏览器、制品、备份恢复与回滚验证。
4. 本地候选、正式 GitHub Release 与客户生产验收始终保持不同状态，不互相替代。
5. 任何必需门禁失败、跳过、重试后通过或缺少外部条件时，不得宣称全量商用交付完成。

## 2. 当前基线与问题定义

整改以现场复现为准，不沿用历史「已完成」自述：

- API `pyproject.toml`、Web 与 README 报告 `1.1.3`，但运行时和 Helm 报告 `1.0.0`；当前版本检查器没有覆盖运行时、Helm 和桌面端。
- Windows `init-env` 因 `whoami.exe` 输出编码与 OEM 代码页假设不一致而失败；隔离 worktree 基线中 `tests.release.test_r2_preflight` 为 18 项中 3 项错误。
- LLM 配置 API 会把 provider key 写入明文 JSON，绕开已有 `SECRETREF:file:` / `SECRETREF:env:` 能力。
- 安全扫描的限流检查请求数低于默认阈值，且失败不计入退出码；扫描可在实际检查失败时错误返回成功。
- API 生产镜像安装 `.[dev]`、默认以 root 运行，并包含已知易受攻击的构建依赖。
- 整仓后端测试至少有 10 个短剧/创意工作室失败；当前 CI 只运行 Web/API 窄化范围。
- 完整 Compose 浏览器链路中的开发任务首次 240 秒超时，依赖重试才通过。
- Tauri 当前只有源码和 `cargo check` 级证据，没有安装制品、启动、连接、签名边界和发布证据。
- 当前正式发布明确排除短剧和桌面端，因此正式 `v1.1.3` 不能证明整仓交付。

## 3. 范围与交付模型

### 3.1 总目标与三个组件门

总目标包含三个组件门：

1. **Web/API 门**：Web 工作台、API、worker、Postgres、Redis、Qdrant、租户、鉴权、审计、调度、工作流、Run Console 与本地 LLM。
2. **短剧门**：脚本/分镜、媒体任务、配音、时间线、产物持久化、失败状态、下载与审计。真实外部图像/视频 provider 属于需要单独授权的外部门禁。
3. **桌面门**：Tauri 编译、应用版本、安装制品、启动、Web/API 连接、升级/回滚边界。正式代码签名需要证书，属于外部门禁。

三个门可以分阶段实现和验证，但只有三者都达到各自定义的出口条件，总目标才允许标记完成。

### 3.2 不允许的范围缩减

- 不得用 Web/API 发布范围通过替代整仓测试通过。
- 不得把短剧源码存在、Null provider 或测试 fixture 当成真实媒体交付证据。
- 不得把 `cargo check` 当成桌面安装包和启动验证。
- 不得把本机 Compose 当成客户生产验收。
- 不得因外部 provider、签名证书或生产环境暂不可用而删除相应门禁。

### 3.3 授权边界

本地代码、测试、构建、隔离容器、真实本地 Ollama 和本地制品验证属于当前授权范围。下列动作仍需在执行前单独确认：

- 调用付费或计费型 LLM、图像、视频 provider。
- 推送分支、创建 PR、合并、创建或移动 tag、发布 GitHub Release。
- 生产或客户环境部署、数据库写入、迁移、恢复、流量切换。
- 使用正式代码签名证书或代表客户/发布角色签字。

## 4. 共享商用交付内核

### 4.1 版本与发布身份

`apps/api/pyproject.toml` 继续作为产品版本事实源，避免引入第二个版本配置中心。

以下位置必须与产品版本一致：

- API project version。
- Web package version。
- `xagent.__version__` 与 `/health` 返回版本。
- Helm `version` 与 `appVersion`。
- Tauri/Cargo 应用版本。
- README 当前版本和候选 tag（提供 tag 时）。

TS SDK 保留独立 SemVer，但其版本、包摘要和兼容产品版本必须写入候选 manifest。版本检查器必须读取所有上述位置，并用回归测试证明任何一个位置漂移都会失败。

整改分支先把当前漂移统一到 `1.1.3`。是否产生下一正式版本，只能在候选门禁全部关闭并获得发布授权后决定；整改本身不创建 tag。

### 4.2 Windows 初始化与权限

Windows 身份获取不再依赖对 `whoami.exe` 字节流代码页的猜测。优先通过 Unicode Windows API 获取 `DOMAIN\\user` 形式的当前身份；仅在 API 不可用时使用可验证的安全回退。

权限流程必须保持：

1. 以 exclusive create 创建环境文件。
2. 写入过程中不覆盖已有文件。
3. 获取当前 Windows 身份。
4. 使用 System32 下的 `icacls.exe` 设置仅当前身份可访问的 ACL。
5. 任一步失败时删除本次创建的残缺文件并返回非零状态。

测试必须覆盖 Unicode 机器名/用户名、API 失败回退、危险身份拒绝、ACL 失败清理和 CLI 证据输出脱敏。

### 4.3 密钥持久化

LLM 配置拆分为非敏感字段和敏感字段：

- 非敏感字段可以继续持久化，例如模型名、代理地址、超时和 fallback 列表。
- 敏感字段包括 proxy、OpenAI、Anthropic、DeepSeek 等 API key。

敏感字段不得以原始值写入磁盘。API 只接受以下两种商用安全行为：

1. 持久化 `SECRETREF:file:<path>` 或 `SECRETREF:env:<name>` 引用。
2. 明确请求 session-only 更新，只在当前进程内生效，重启后消失。

`SECRETREF:vault:` 在实现前继续 fail-fast，不伪装为可用。GET 接口只返回是否配置、来源类型和掩码状态，永不返回引用解析后的 secret。

启动时发现历史明文覆盖文件：

- full/enterprise 模式拒绝加载敏感明文并给出明确迁移错误。
- lite 模式忽略敏感明文、记录不含值的警告，并保留非敏感配置。
- 提供一次性、本地运行的迁移/清理命令，只删除敏感字段，不上传、不调用 provider。

配置文件使用原子替换和 owner-only 权限；写入失败不得破坏上一份有效配置。

### 4.4 安全扫描

安全扫描的每项检查都返回结构化结果，并统一汇总到退出码。以下检查均为必需：

- 安全响应头。
- full 模式未认证业务端点返回 401/403。
- 跨租户 header 注入拒绝。
- 租户数据隔离。
- SQL 注入输入不造成结构破坏。
- 限流在测试专用、显式阈值下确定性触发 429。

扫描不得依赖生产默认阈值推测请求次数。测试环境通过受控配置设置较低阈值，扫描从服务暴露的配置或命令参数读取期望值。任何检查失败、注册前置失败或响应结构异常都必须返回非零退出码和脱敏 JSON 证据。

### 4.5 依赖、镜像与供应链

API 镜像采用多阶段构建：构建阶段可以安装构建工具，运行阶段只安装锁定的生产依赖和应用代码。运行阶段必须：

- 使用非 root 用户。
- 不包含编译器、Git、测试框架或 dev extra。
- 通过 `pip check` 和漏洞审计门禁。
- 生成 SBOM，并记录基础镜像与产物 digest。

Web、SDK 和桌面端分别使用 lockfile 执行生产依赖审计。缺失 lockfile 视为门禁失败，不降级为警告。Helm/Compose 商用模板使用不可变版本或 digest，不以 `latest` 作为交付值。

漏洞处置只有三种有效状态：已升级修复、证明不在交付制品中、或经负责人限时接受并记录到候选 manifest。未知或未审计不算通过。

## 5. 组件门设计

### 5.1 Web/API 门

出口条件：

- 完整 Web/API 后端发布范围通过，跳过项逐项证明不属于该门或在独立集成环境补测。
- 前端 lint、精确豁免门、unit、typecheck、build 和生产依赖审计通过。
- TS SDK 测试、类型、打包和生产依赖审计通过。
- 隔离 Compose 的 postgres、redis、qdrant、api、worker、web 全部健康，迁移位于 head。
- 使用真实本地 Ollama 完成对话、工作流、调度、文件产物和恢复链路。
- 浏览器覆盖登录、对话、Run Console、刷新恢复、调度、技能导入、开发任务、产物下载和租户隔离。
- Playwright 最终商用门禁禁用 retry；单次超时或 flaky 均为失败。

### 5.2 短剧门

先修复当前整仓测试暴露的配音、Null/local media、task id、持久化、产物 schema 和 delivery summary 根因。测试数据不得默认访问公共网络服务。

出口条件：

- 单元与集成测试全部通过，无 `partial`/`blocked` 状态与预期 `produced`/`ready` 不一致。
- Null/local provider 的语义明确：若能力是占位验证，结果必须标记为 fixture/local，不得伪装真实供应商产物。
- 至少生成一套可打开、可下载、可校验摘要的本地短剧交付包，包含分镜、时间线、音频/媒体引用、失败记录和审计元数据。
- 真实外部图像/视频 provider 的一次性验证在获得费用与提交授权后执行；未知提交结果标记为 `submission_unknown`，不自动重试。

### 5.3 Tauri 桌面门

出口条件：

- `cargo fmt --check`、Clippy、测试、locked build 和依赖漏洞审计通过。
- Tauri/Cargo 版本与产品版本一致，生成的 schema 不产生未解释漂移。
- 生成 Windows 安装制品并记录 SHA-256、大小、架构和构建 SHA。
- 在隔离测试用户或测试环境完成安装、首次启动、连接本地 Web/API、关闭、重新启动和卸载验证。
- 无正式签名证书时，候选只能标为 unsigned local candidate；正式桌面商用发布必须补齐签名、证书主体、时间戳和安装验证。

## 6. 同一 SHA 的证据链

所有门禁输出统一绑定：

- repository、branch、commit SHA。
- dirty/clean 状态。
- 工具版本和运行时间。
- 命令、退出码、通过/失败/跳过计数。
- 构建制品摘要和镜像 digest。
- 运行环境标识与配置摘要（不含 secret）。

证据分为三层：

1. **本地候选证据**：当前 worktree 和隔离运行环境产生。
2. **正式发布证据**：远端同一 SHA 的 CI、不可变镜像、tag、Release 和签字；需要发布授权。
3. **客户生产证据**：客户环境部署、迁移、监控、备份恢复、回滚和客户签字；不能由前两层推断。

本地候选证据写入独立的机器可读 manifest 和人类可读报告。报告不得把历史日志复制为当前证据；每次候选变化后必须全部重新运行。

## 7. 备份、恢复与回滚

本地隔离演练至少验证：

1. 从零部署当前候选并写入可识别的测试数据。
2. 备份 Postgres、Qdrant 和应用审计/产物数据。
3. 执行相邻版本迁移或等价升级演练。
4. 验证新版本健康和核心链路。
5. 回滚到上一候选并恢复数据。
6. 复核数据完整性、租户隔离、产物可打开和审计链连续。

回滚脚本只能操作带本次审计 project label、明确路径和候选 digest 的资源。不得触碰现有生产或其他项目容器。

## 8. 错误处理与 fail-closed 原则

- 版本漂移、secret 明文、扫描异常、依赖审计缺失、浏览器 flaky、制品摘要缺失均直接阻断对应门。
- 必需测试的 skip 必须有可核对的外部条件和替代验证；无说明 skip 视为失败。
- 外部付费提交未知时不重试，状态保持 `needs_attention/submission_unknown`。
- 构建或验证产生的临时文件必须限定在候选工作树或带唯一标签的隔离环境，并在结束时清理。
- 文档状态只在证据通过后更新；不得先写「已商用」再补证据。

## 9. 实施顺序

1. 建立共享 P0：版本、Windows 初始化、密钥、安全扫描、供应链。
2. 修复整仓测试根因，关闭短剧代码级红灯。
3. 稳定 Web/API Compose 与无 retry 浏览器链路。
4. 完成桌面构建、安装和连接门。
5. 生成三类制品、SBOM、摘要和统一候选 manifest。
6. 在同一 SHA 上执行隔离部署、真实本地模型、备份恢复和回滚。
7. 形成正式发布候选报告；在获得授权后再进入远端 PR/tag/Release 和客户环境阶段。

## 10. 完成判定

只有以下条件同时成立，目标才算完成：

- 目标中列出的每个缺陷和证据缺口均有对应测试或运行证据关闭。
- Web/API、短剧和桌面三个组件门全部通过。
- 共享安全、依赖、镜像和版本门全部通过。
- 同一 SHA 的本地候选证据完整，工作树干净。
- 正式发布和客户生产仍缺少授权或外部条件时，必须保持各自未完成状态；不得把本地候选改名为正式发布或客户验收。

若尚未授权远端、付费供应商或客户操作，本地代码整改阶段可以收口并形成候选，但总目标不得标记完成。总报告必须明确列出正式发布与客户生产的剩余外部门禁；正式 GA 与客户验收只能在对应证据真实产生后成立。
