# G3-C1 HA / K8s 真实验证计划

> 适用阶段：G3 企业级长期运营
>
> 用途：把 G3-C1 从“方向与边界已定义”推进到“真实验证可执行”，明确 HA / K8s / secret 管理 / 多实例一致性要在什么环境、按什么标准、输出什么证据来验证。

---

## 1. 目标

本计划的目标是：

> **为 `xagent` 的 HA / K8s 包提供第一份真实验证计划，使 G3-C1 不再只停留在方向定义，而进入可验证、可判定通过与否的状态。**

---

## 2. 验证范围

本次验证只覆盖 G3-C1 的四个核心问题：

1. API 多副本是否能稳定工作；
2. worker 多副本是否会引入重复消费 / 幂等问题；
3. Helm / K8s 渲染是否已具备最小平台化入口；
4. secret 注入方向是否已明确，不会把 env 值误写成已支持 secretRef。

本次验证**不**要求一次性完成：
- 正式多集群部署；
- 生产级 secret manager 落地；
- 企业级流量治理；
- 完整性能压测平台。

---

## 3. 验证环境

### 3.1 当前推荐验证环境

优先采用：

- **等价验证环境**
  - 单机或本地 K8s / 等价容器环境
  - 用于 Helm 渲染、多副本结构检查、secret 注入方式检查

### 3.2 环境前提

必须具备：

- 可运行 Helm 模板渲染；
- 至少可以模拟 API / worker 多副本配置；
- 可以检查 `security.jwtSecret` 等关键配置在模板中的注入路径；
- 可以保留输出日志和渲染产物。

---

## 4. 验证项

### 4.1 Helm / K8s 渲染验证

运行：

```powershell
helm template xagent deploy/helm --set api.enabled=true --set security.jwtSecret=<32+ chars random>
```

期望：
- chart 能成功渲染；
- `jwtSecret` 仍保持 fail-fast；
- API / worker 模板能够生成；
- 不出现依赖危险默认值才能渲染成功的情况。

### 4.2 多实例结构验证

检查：
- `replicaCount` 可提升到 >1；
- worker `replicas` 可提升到 >1；
- autoscaling 入口存在；
- chart / values 中没有把多实例写成“已验证完成”的事实。

输出：
- 渲染结果摘要
- 当前 chart 能表达的多实例结构说明

### 4.3 secret 管理方向验证

检查：
- 当前是否仍以 env / values 注入为主；
- 文档中是否已明确 secretRef / external secret manager 是后续目标方向；
- 没有把“平台化 secret 注入”写成已经完成。

输出：
- 当前注入方式表
- 目标注入方式表
- 差距说明

### 4.4 多实例一致性验证清单

至少列出后续必须验证的对象：
- API 状态读模型
- worker 任务消费
- queue / broker 行为
- run / task / workflow 的幂等与可追溯性
- 回滚后多副本状态收敛

输出：
- 一份“后续必须验证”的一致性清单，而不是模糊描述

---

## 5. 通过标准

G3-C1 的真实验证通过，不等于“K8s 已正式上线”，而是至少满足：

1. Helm / K8s 最小模板已被验证可渲染；
2. API / worker 多实例结构已被验证可表达；
3. secret 注入当前态与目标态差距已明确；
4. 多实例前必须验证的一致性对象已经列成清单；
5. 有一份可审阅的验证输出，而不是只在口头里说“后续做 HA”。

---

## 6. 证据要求

本计划要求输出的最小证据包括：

- Helm template 输出摘要
- 多实例相关 values / 渲染片段
- 当前 secret 注入方式与目标方式对照
- 一致性验证清单
- 最终判定：
  - 通过 / 不通过
  - 哪些部分仍阻塞
  - 下一步责任包

建议归档到：
- `docs/coordination/reports/commercialization-g3-c1-ha-k8s-verification.md`

---

## 7. 当前结论

当前 `G3-C1` 已完成方向定义；
这份计划的作用是让它进入下一状态：

> **可执行验证**

只有完成这一步，`G3-C1` 才能从“定义完成”走向“验证完成”。
