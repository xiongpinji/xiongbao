# Roadmap v2 B 自动化运营增强包

> 适用阶段：Roadmap v2
>
> 用途：在当前商用交付标准已达成的前提下，把自动化运营增强方向冻结成一份执行包，为后续告警联动、自动恢复、自动证据归档与自动运行态汇总提供统一入口。

---

## 1. 目标

B 自动化运营增强包的目标是：

> **把 `xagent` 从“已有人工值守与恢复能力”继续推进到“更多依赖系统自动发现、自动归档、自动恢复与自动汇总”的运营形态。**

这一步不要求立刻完成全自动运营，但必须明确：

- 哪些运营动作仍依赖人工；
- 哪些可以优先自动化；
- 自动化增强后要减少什么人工成本；
- 自动化的最小输出物是什么。

---

## 2. 当前已有基础

当前已经具备：

- 运维手册与最小排障路径；
- 稳定性 / 恢复包与演练记录；
- 可观测 / 告警方向包；
- 发布 / 回滚与签字证据包；
- 支持升级路径与分层支持模型。

## 3. 当前缺口

### 3.1 告警联动缺口
- 当前知道哪些信号危险，但仍多靠人工发现与人工聚合；
- 尚未形成自动告警升级与自动通知的统一设计入口。

### 3.2 自动恢复缺口
- 当前恢复路径可执行，但仍以人工判断与人工执行为主；
- 还没有把可自动恢复的动作正式抽象出来。

### 3.3 自动证据归档缺口
- 当前证据需要人工记录、人工归档、人工回填文档；
- 后续应明确哪些证据可以自动抓取和自动归档。

### 3.4 自动运行态汇总缺口
- 当前 Goal / Run / Workflow / Release 的结果可以查看，但还没有统一自动汇总入口；
- 需要继续减少“看多份材料才能拼出全貌”的成本。

---

## 4. 下一步输出物

自动化运营增强包后续应产出：

- 自动告警联动方向说明
- 自动恢复动作清单
- 自动证据归档入口
- 自动运行态汇总入口
- 自动化运营验证包

---

## 5. 当前结论

B 自动化运营增强包的作用不是立刻把运维变成全自动，而是：

> **把自动化运营正式拉成一条新主线，并给后续真实实现与验证提供统一入口。**
