> 适用范围：`apps/web` 当前未提交改动。
> 目标：把“收口清单”变成可直接执行的页面点击验收单。
> 执行前提：
>
> - 后端可访问：`http://127.0.0.1:8000`
> - 前端可访问：`http://127.0.0.1:3000`
> - 当前已确认 `typecheck` 与 `build` 通过

---

## 1. 验收记录模板

每个页面按同一格式记录，避免只记“好像有问题”：

- **步骤：** 点了什么、输入了什么。
- **预期：** 应该看到什么。
- **实际：** 实际出现了什么。
- **结果：** 通过 / 不通过 / 待确认。
- **备注：** 截图路径、报错文案、接口状态码。

建议记录成下面格式：

```markdown
### 验收项：登录后跳转
- 步骤：输入 admin / admin，点击“登录”
- 预期：跳转到 /chat
- 实际：跳转到 /chat，页面正常显示
- 结果：通过
- 备注：无
```

## 2. 启动前准备

### 2.1 启动后端

在 `apps/api` 目录执行：

```bash
xagent serve
```

### 2.2 启动前端

在 `apps/web` 目录执行：

```bash
npm run dev
```

### 2.3 启动后先做 3 个快速确认

- [ ] 打开 `http://127.0.0.1:8000/health`，看到 `status=ok`
- [ ] 打开 `http://127.0.0.1:3000`，页面可加载
- [ ] 如走登录模式，确认 `admin / admin` 可登录

## 3. 第一轮：登录与进入路径

> 目标：先确认“进得去”。如果第一轮不稳，不要继续验深层页面。

### 3.1 登录页

**入口：** `/login`

- [ ] 页面加载后，确认 Logo、标题、输入框、按钮样式正常。
- [ ] 用户名为空、密码为空时，登录按钮应不可用。
- [ ] 输入用户名但不输入密码时，登录按钮仍不可用。
- [ ] 输入用户名密码后，登录按钮应可点击。

**记录重点：**
- 是否有布局错位
- 是否有按钮状态错误
- 深色背景下文字是否可读

### 3.2 正常登录

**步骤：**
1. 输入 `admin`
2. 输入 `admin`
3. 点击“登录”

**预期：**
- 跳转到 `/chat`
- 不停留在 loading
- 不显示错误提示

**失败时记录：**
- 是否出现错误提示
- 错误提示具体文案
- 后端日志是否有 `/auth/login` 失败

### 3.3 匿名进入

**步骤：** 点击“匿名进入工作区”

**预期：**
- 跳转到 `/chat`
- 页面正常可见
- 刷新后仍处于工作区，而不是被踢回登录页

**额外检查：**
- [ ] 匿名进入后直接访问 `/agents`
- [ ] 匿名进入后直接访问 `/professional?mode=workflow`
- [ ] 匿名进入后直接访问 `/runs/不存在的id`

**记录重点：**
- 哪些页面匿名可进
- 哪些页面匿名会 401 或 fallback

## 5. 第三轮：核心执行链路

> 目标：先验“主链路能走”，再看辅助页。

### 5.1 Chat 页

**入口：** `/chat`

#### 用例 A：空输入
- [ ] 输入框为空时，“发送”按钮应不可用。

#### 用例 B：普通任务提交
- [ ] 输入一句简单任务，例如“写一个函数”
- [ ] 点击发送

**预期：**
- 出现用户消息气泡
- 出现“正在分析任务并调用 Agent...”状态
- 若 SSE 成功，应显示流式结果或最终结果
- 若 SSE 失败，应回退到普通 `runAgent`
- 成功后出现“查看运行详情”按钮

**记录重点：**
- 是走了 SSE 还是 fallback
- 错误提示是否可读
- 是否拿到了 `runId`

#### 用例 C：运行详情跳转
- [ ] 点击“查看运行详情”
- [ ] 确认进入 `/runs/:runId`

### 5.2 Workflow 页

**入口：** `/professional?mode=workflow`

#### 用例 A：手动新增步骤

- [ ] 确认画布中新增一个节点

#### 用例 C：删除步骤

- [ ] 确认列表项消失
- [ ] 确认节点与相关边也消失

#### 用例 D：创建并执行
- [ ] 至少保留 1 个有目标的步骤
- [ ] 点击“创建并执行”

**预期：**
- 无前端报错

### 5.3 Creative / Drama 页

**入口：** `/professional?mode=drama`

#### 用例 A：创建画布

### 5.4 Run Detail 页

#### 用例 A：有效 runId
- [ ] 从 Chat / Workflow / Creative 成功跳转进入

#### 用例 D：fallback 动作

## 8. 问题分级规则

验收时，把问题分成 3 类，避免所有问题都堆成一团。

### 阻断

满足任一项：

- 页面打不开 / 白屏
- 主链路无法走通
- 登录或路由跳转失效
- 点击关键按钮无反应且无提示
- 匿名 / 登录态把用户卡死在错误状态

### 非阻断

满足任一项：

- 文案误导
- fallback 提示不清楚
- 某些次级入口行为不顺
- 样式错位但不影响主流程

### 后续优化

满足任一项：

- chunk 过大 warning
- 视觉细节可再打磨
- 演示态标识可增强
- 静态假数据后续接真数据

如果时间有限，按下面顺序走：

1. 登录页

9. Agents / Memory / OpenSource / Settings 做快速冒烟
