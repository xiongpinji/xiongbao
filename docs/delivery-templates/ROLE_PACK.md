# 标准角色包（P3 商业复制）

> 用途：交付/试点/运营中各角色的职责矩阵与最小人力配置。

## 1. 角色定义

| 角色 | 职责 | 关键交付物 |
|---|---|---|
| TL（技术负责人） | 候选冻结、技术风险裁决、签发技术口径 | R5 审查包确认 |
| QA（质量） | 质量门禁执行、回归证据、验收测试 | pytest/构建/E2E 证据 |
| DevOps（交付运维） | 部署、演练、备份恢复、告警值守 | R4 演练记录、巡检记录 |
| Owner（签发人） | 发布签发、边界接受、对外口径 | 签发记录（R5 §0.4 格式） |

## 2. 配置模式

### 2.1 单人交付模式（当前默认）

同一人覆盖全部四角（参照 SUPPORT_ESCALATION_PATH_V1：owner `canqu` 承担 L1-L4）。
要求：每个角色动作仍**分别留痕**（签发记录、测试证据、演练记录分开归档），避免角色混同导致证据缺失。

### 2.2 小组模式（2-3 人）

- A：TL + Owner
- B：QA + DevOps（或再拆分）
要求：签发人与部署执行人不同ID，形成最小相互校验。

### 2.3 客户现场模式

- 我方：TL + DevOps
- 客户：Owner（业务签发）+ QA（业务验收）
要求：客户侧签发模板与本包 §1 一致。

## 3. 交接清单（人员变更时）

- [ ] 在途事项清单（任务板导出）
- [ ] 未闭环边界清单（SOT §10 当前版）
