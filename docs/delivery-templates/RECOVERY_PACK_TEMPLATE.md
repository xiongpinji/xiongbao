# 标准恢复包模板（P3 商业复制）

> 用途：灾难恢复（误删/损坏/主机丢失）的标准动作集。依据 OPERATIONS_MANUAL_V1 与 R12 迁移诊断。

## 1. 恢复对象与 RTO/RPO

| 项 | 内容 |
|---|---|
| 场景 | `<误删数据 / DB 损坏 / 整机丢失>` |
| RTO（恢复时间目标） | `<如 2h>` |
| RPO（数据丢失容忍） | `<如 24h，对应每日备份>` |
| 最近备份 | `<位置 + 校验值>` |

## 2. 恢复前检查

- [ ] 备份完整性校验通过（可打开/可挂载/行数合理）
- [ ] 恢复目标环境干净（无残留半损坏状态）
- [ ] secret 可用（secretRef 引用路径可达，不依赖原机器本地文件）

## 3. 恢复步骤

1. 重建基础环境（compose/helm 拉起依赖件：Postgres/Redis/Qdrant）
2. 恢复 DB（pg_restore 或 SQLite 文件归位）
3. `alembic current` 核对迁移 head，必要时 `alembic upgrade head`
4. 恢复数据目录（skills/scheduler/uploads/qdrant snapshot）
5. 启动应用，smoke：`/health` `/ready` 登录 主链路一发
6. 数据抽验（关键业务对象数量与样本）

## 4. 恢复后动作

- [ ] 事故时间线记录（发现→定位→恢复→验证）
- [ ] 根因与防复发措施
- [ ] 备份策略复核（频率/保留/异地）

## 5. 演练纪律

- 每 `<季度>` 至少一次恢复演练；演练证据归档到 evidence 目录
- 未演练过的备份视为不存在
