X-Agent Roadmap v2（商用交付后的增强路线）

  • 日期：2026-07-20
  • 主题：在当前商用交付标准已达成的前提下，定义下一轮增强与规模化方向
  • 适用范围：xagent 当前主仓、后续平台化、自动化运营、容量提升与商业复制能力建设

1. 当前基线

当前 xagent 已完成：

  • G1 内部试点可稳定使用
  • G2 正式商用 GA
  • G3 企业级长期运营治理与首轮验证
  • G0 xagent 商用完整交付

这意味着：

后续工作不再是“是否达到商用交付标准”，而是“在已经达到商用交付标准的前提下，下一轮增强要优先投向哪里”。

因此，Roadmap v2 的所有方向都应理解为： - 增强项 - 规模化项 - 平台化项 - 复制能力项

而不是重新回到“项目是否可交付”的旧问题上。

2. Roadmap v2 的目标

Roadmap v2 的总目标是：

把已经完成商用交付的 xagent，继续推进为更易复制、更低运维成本、更强平台化、更可规模扩展的产品化系统。

2.1 总体原则

  1. 不再重复把“商用达标”作为主目标；
  2. 优先做可复制、可扩展、可平台化的方向；
  3. 所有后续工作都应服务于更强交付效率与更低长期维护成本；
  4. 新增强项不得回退已有 G0/G1/G2/G3 的完成结论；
  5. 继续沿用 Goal / 执行包 / 验证闭环的推进方式。

3. 方向 A：平台化增强

目标

把当前可运行、可交付的系统，推进成更标准化的平台部署形态。

当前缺口

  • secretRef / external secret manager 仍主要停留在方向层；
  • Helm chart 已有入口，但未完全产品化；
  • 多环境模板和平台级注入方式仍有手工依赖。

下一步任务方向

  • 完整 K8s / Helm 平台化补齐
  • secretRef / external secret manager 真正落地
  • 标准环境模板（dev / staging / prod / enterprise）
  • 平台级配置治理与差异控制

预期结果

  • 客户环境或平台团队可以更低成本接入；
  • 交付不再过度依赖单机/Compose 形态；
  • secret 与配置注入从“文档说明”走向“平台能力”。

4. 方向 B：自动化运营增强

目标

降低人工值守、排障和材料归档的成本。

当前缺口

  • 观测、恢复、证据归档虽然已具备基础，但仍有较多人工判断；
  • 发布后故障定位和恢复步骤还依赖人工执行与记录；
  • 长任务状态、恢复动作和材料沉淀仍可继续自动化。

下一步任务方向

  • 自动告警联动
  • 自动恢复与自动归档
  • 更强的 run / workflow 证据链自动生成
  • 发布后观测结果自动汇总

预期结果

  • 运营从“靠人盯”走向“系统先发现、先收集、先归档”；
  • 降低试点到正式运营的人力负担；
  • 提升问题响应的一致性。

5. 方向 C：容量与性能增强

目标

从“知道边界”推进到“实证边界”。

当前缺口

  • G3-C4 已冻结容量方向与基础验证入口；
  • 但完整压测结论、长期吞吐边界、多实例扩缩容实证仍未完成；
  • 瓶颈对象虽已明确，但缺更正式的数据支撑。

下一步任务方向

  • 正式压测基线
  • 多实例一致性与扩容实证
  • 队列 / 缓存 / LLM 路径瓶颈治理
  • 更清晰的容量建议与限制策略

预期结果

  • 团队能够给出更可信的规模与容量口径；
  • 扩容不再基于经验猜测；
  • 面向企业用户时，可提供更正式的容量边界说明。

6. 方向 D：商业复制增强

目标

让交付不仅可做成一次，还能低成本复制到不同客户 / 团队 / 场景。

当前缺口

  • 当前交付材料已经完整，但更多是“当前项目可交付”；
  • 还缺更标准化的模板、角色包、行业场景包；
  • 商用交付经验还没有沉淀成可复制资产。

下一步任务方向

  • 标准交付模板
  • 标准试点包 / 升级包 / 恢复包
  • 不同角色模板（管理员 / 运维 / Owner / 审核者）
  • 不同场景 / 行业的交付变体包

预期结果

  • 交付模式可以复制；
  • 新客户 / 新环境进入成本降低；
  • 团队从“逐单经验交付”走向“资产化交付”。

7. 方向 E：产品增强

目标

在不回退已达成商用标准的前提下，继续提升产品竞争力。

当前缺口

  • 当前 Goal / taskboard / release / recovery 主链已经建立；
  • 但还可以继续增强自动推进、体验、证据自动化与产品深度；
  • 后续增强应建立在稳定主链之上，而不是重新破坏交付基线。

下一步任务方向

  • Goal / taskboard 自动推进能力增强
  • review / recover / evidence 自动化增强
  • 更强的产品工作台体验
  • 更细粒度的执行和治理视图

预期结果

  • xagent 从“可交付”继续迈向“更强产品化能力”；
  • 提升与同类系统相比的产品差异化。

8. 推荐优先顺序

如果以投入产出比排序，我建议：

  1. 平台化增强（A）
  2. 自动化运营增强（B）
  3. 容量与性能增强（C）
  4. 商业复制增强（D）
  5. 产品增强（E）

原因

  • 平台化和运营自动化最直接影响后续交付效率；
  • 容量与性能决定能否稳妥扩张；
  • 商业复制增强决定交付是否能规模化复用；
  • 产品增强应建立在前面三者已稳的前提下持续推进。

9. 当前结论

Roadmap v2 的定位已经明确：

它不是“补齐商用标准”，而是“在商用标准达成之后，继续把 xagent 推向更强的平台化、运营自动化、容量实证和商业复制能力”。

因此，后续任何新增工作都应默认按 Roadmap v2 的方向归类，而不再回退到 G0/G1/G2/G3 是否完成的争议中。
